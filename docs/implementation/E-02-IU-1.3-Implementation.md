## 1. Purpose

Define the **implementation design** for the **Freeze Transaction Boundary**.

IU-1.3 **shall establish** transaction ownership, transaction opening conditions, rollback boundary, failure propagation, and downstream hand-off required by the Freeze Engine.

IU-1.3 **shall consume** the certified engineering baselines from [`E-02-IU-1.1-Completion.md`](E-02-IU-1.1-Completion.md) and [`E-02-IU-1.2-Completion.md`](E-02-IU-1.2-Completion.md).

IU-1.3 **shall not** materialize snapshots, perform the Phase 3 final commit, or write the primary freeze audit.

This document implements [`E-02-Phase-1-Implementation-Plan.md`](E-02-Phase-1-Implementation-Plan.md) §IU-1.3 and **shall not redefine** architecture decisions in [`E-02-Architecture.md`](E-02-Architecture.md).

## 3. Objective

Establish **one authoritative Freeze Transaction Boundary** after successful validation and candidate identity assignment.

The boundary **shall provide**:

| Capability | IU-1.3 scope |
|------------|--------------|
| Single transaction ownership | ✓ Define · enforce |
| Atomic work envelope | ✓ Define · open |
| Rollback authority | ✓ Define · execute pre-commit rollback |
| Failure propagation | ✓ Define |
| Phase 2 materialization hand-off | ✓ Define |
| Phase 3 commit hand-off | ✓ Define |

IU-1.3 does **not** perform materialization or final commit inside this IU.

---

## 4. Phase 1 input baselines

IU-1.3 **shall consume** without silent redefinition:

### IU-1.1 — Freeze Identity Baseline

| Rule | Requirement |
|------|-------------|
| Correlation root | Freeze Event identity |
| Ownership | `FreezeContext` owns candidate identity |
| Reuse | Identity reuse prohibited — new attempt → new candidate after rollback |

### IU-1.2 — Freeze Validation Baseline

| Outcome | Transaction rule |
|---------|------------------|
| **VALID** | Only outcome that may create a **new** transaction attempt |
| **INVALID** | Fail closed — no transaction |
| **IDEMPOTENT RETURN** | Return existing committed primary — **no** new transaction |
| **RETRYABLE** | **No** new transaction |
| **CONFLICT** | Reserved — fail closed if emitted |

---

## 5. Transaction Entry Contract

A **new** Freeze Transaction **may open** only when **all** conditions hold:

| # | Condition |
|---|-----------|
| 1 | Validation Result = **VALID** |
| 2 | Candidate Freeze Event identity **has been assigned** |
| 3 | No committed primary has superseded the attempt |
| 4 | No competing transaction owns the freeze boundary |

Any failure **shall prevent** transaction entry.

**Design questions DQ-001–DQ-003:** Entry under non-VALID outcomes → **NO**. IDEMPOTENT RETURN opens transaction → **NO**. RETRYABLE opens transaction → **NO**.

---

## 6. Transaction ownership

| Rule | Requirement |
|------|-------------|
| **Owner** | Freeze Engine orchestration layer |
| **Cardinality** | Exactly **one** active transaction owner per meeting freeze boundary |
| **Association** | `meetingId` · `propertyId` · `freezeEventId` · attempt identity · transaction state |
| **Transfer** | Ownership **shall not** be transferred implicitly between callers |

Mitigates **R-009** (multiple active owners).

---

## 7. Transaction state model

```
UNOPENED
    ↓
  OPEN
    ↓
MATERIALIZATION_READY
    ↓
COMMIT_READY
    or
ROLLING_BACK
    ↓
ROLLED_BACK
```

| State | Meaning |
|-------|---------|
| **UNOPENED** | Validation or identity prerequisites not yet satisfied |
| **OPEN** | Transaction boundary acquired; Phase 2 materialization not yet certified complete inside envelope |
| **MATERIALIZATION_READY** | Authorized to hand control to Phase 2 — **does not** mean snapshots persisted |
| **COMMIT_READY** | Downstream materialization reported success within same atomic work envelope — authorizes Phase 3 commit processing; IU-1.3 **does not** perform final commit |
| **ROLLING_BACK** | Failure before successful final commit; all transaction-scoped work must be abandoned |
| **ROLLED_BACK** | Rollback completed; no partial freeze may remain durable |

### Terminality

| State | Terminal? |
|-------|-----------|
| **ROLLED_BACK** | **Yes** — for that attempt (IU-1.3 model) |
| **Committed** | **Phase 3 only** — **not** an IU-1.3-owned state |

Retry after rollback requires a **new attempt** per IU-1.1 identity lifecycle — prior candidate identity **shall not** be silently reused (DQ-007).

---

## 8. Atomic work envelope

IU-1.3 **shall establish** one atomic work envelope capable of containing future Phase 2 and Phase 3 operations.

```
Transaction Open (IU-1.3)
        ↓
Phase 2 Materialization
  · Voter Snapshot
  · Resolution Snapshot
  · Frozen Motions
        ↓
Phase 3
  · Freeze marker
  · Phase transition
  · Primary audit
        ↓
Final Commit (Phase 3)
```

All operations above **must ultimately participate** in **one atomic transaction**. IU-1.3 establishes the **boundary only** — it does **not** execute downstream operations.

Mitigates **R-010** (partial durable freeze) and **R-011** (Phase 2 independent transaction).

---

## 9. Rollback Contract

Any failure **before** successful Phase 3 final commit **shall cause rollback** of the entire atomic work envelope.

Rollback **shall guarantee**:

| Guarantee | Requirement |
|-----------|-------------|
| No durable partial Voter Snapshot | ✓ |
| No durable partial Resolution Snapshot | ✓ |
| No durable partial Frozen Motions | ✓ |
| No durable freeze marker | ✓ |
| No durable phase transition | ✓ |
| No durable primary audit | ✓ |
| No falsely committed Freeze Event | ✓ |

Rollback **shall preserve** ability to retry per Recovery Model (RM-2). **DQ-006:** Rollback covers all downstream artifacts before final commit → **YES**.

---

## 10. Failure propagation

| Rule | Requirement |
|------|-------------|
| Failures propagate to transaction owner | ✓ |
| **Shall not** swallow errors | ✓ |
| **Shall not** convert failure into success | ✓ |
| **Shall not** commit partial state | ✓ |
| **Shall not** silently retry inside transaction boundary | ✓ |

Retry decision belongs to **orchestration after rollback completes** (R-013).

---

## 11. Idempotency interaction

IU-1.3 **shall preserve** IU-1.2 outcome semantics:

| Condition | IU-1.3 behavior |
|-----------|-----------------|
| Committed primary exists | **IDEMPOTENT RETURN** — no transaction opened |
| Another active attempt owns boundary | **RETRYABLE** — no second transaction opened |
| Previous attempt rolled back | New authorized attempt may retry |
| Prior candidate identity after rollback | **Shall not** be reused unless formal architecture revision |

---

## 13. Phase 2 hand-off contract

Single successful hand-off path:

```
OPEN
    ↓
MATERIALIZATION_READY
    ↓
Phase 2
```

| Rule | Requirement |
|------|-------------|
| Phase 2 begins **only** inside authoritative atomic work envelope | ✓ |
| Phase 2 **shall not** open independent freeze transaction | ✓ (DQ-004: **NO**) |
| Phase 2 **shall not** replace Freeze Event identity | ✓ |

---

## 14. Phase 3 hand-off contract

After Phase 2 reports successful materialization inside same work envelope:

```
MATERIALIZATION_READY
    ↓
COMMIT_READY
    ↓
Phase 3
```

**Phase 3 owns:** final atomic commit · meeting freeze marker · phase transition · primary audit · committed terminal state.

IU-1.3 **shall not** perform those operations (**DQ-005:** IU-1.3 performs final DB commit → **NO**).

Mitigates **R-012**.

---

## 15. Architecture constraints

IU-1.3 **shall preserve**:

| Constraint set | Application |
|----------------|-------------|
| **FA-1 – FA-4** | Entry only after VALID; fail closed on entry failure |
| **CM-1 – CM-7** | Envelope preserves single-event correlation for future stages |
| **RM-1 – RM-5** | Rollback before commit; no repair of committed state in IU-1.3 |
| **Freeze Contract** | Boundary wraps future outputs; no outputs in IU-1.3 |
| **PI-1 – PI-5** | Single owner · no partial freeze · no snapshot persist in IU-1.3 |
| **IU-1.1 baseline** | Identity lifecycle · correlation root |
| **IU-1.2 baseline** | Validation outcomes · entry gating |

---

## 16. Engineering risks

| ID | Risk | Mitigation |
|----|------|------------|
| **R-008** | Transaction opened before VALID | Strict Transaction Entry Contract §5 |
| **R-009** | Multiple active owners | Single transaction ownership §6 |
| **R-010** | Partial durable freeze after downstream failure | Atomic work envelope §8 + mandatory rollback §9 |
| **R-011** | Phase 2 opens independent transaction | Phase 2 Hand-off Contract §13 |
| **R-012** | IU-1.3 performs Phase 3 commit | COMMIT_READY hand-off only §14 |
| **R-013** | Silent retry inside transaction | Failure propagation §10 |

Phase 1 plan **R-004** (rollback failure) addressed by Rollback Contract §9.
