## 1. Purpose

Define the **implementation design** for **IU-2.1 — Voter Snapshot Materialization**.

IU-2.1 **shall** materialize the freeze-time voter domain inside the authoritative Phase 1 atomic work envelope.

IU-2.1 **shall consume** the E-01 voter snapshot foundation without redefining identity, correlation, immutability, or legacy semantics.

IU-2.1 **shall not** materialize Resolution Snapshot, materialize Frozen Motions, perform final commit, write primary audit, or perform voting authorization.

This document implements [`E-02-Phase-2-Implementation-Plan.md`](E-02-Phase-2-Implementation-Plan.md) §IU-2.1 and **shall not redefine** architecture decisions in [`E-02-Architecture.md`](E-02-Architecture.md).

## 3. Objective

Materialize **one complete, correlated freeze-time Voter Snapshot domain** for the authoritative Freeze Event.

The result **shall** represent the approved eligibility source at the freeze boundary.

Output **remains inside** the active atomic work envelope.

No durable partial freeze **may** exist independently of Phase 3 final commit.

IU-2.1 may begin **only** when **all** conditions hold:

| Condition | Requirement |
|-----------|-------------|
| Validation result | **VALID** |
| Transaction state | **MATERIALIZATION_READY** |
| `freezeEventId` | Exists — candidate identity assigned |

| Attempt identity | Exists |
| Transaction ownership | Valid — authoritative owner active |

If any condition is missing or inconsistent: **FAIL CLOSED**. No voter snapshot rows **shall** be materialized.

## 5. Authoritative eligibility source

### 5.1 Source authority

IU-2.1 **shall** define **one authoritative live voter eligibility source** — the **Production Eligibility Contract (PEC)** recovered in [`RC010-B`](../rc/RC010-B-Production-Freeze-Contract-Recovery.md) §7.3.

| Field | Definition |
|-------|------------|
| **Source relation** | `public.property_members` |
| **Meeting scope** | Rows for `FreezeContext.propertyId` where meeting binding is verified via `owner_vote_meetings.id = FreezeContext.meetingId` and `owner_vote_meetings.property_id = FreezeContext.propertyId` |
| **Member filter** | `status = 'active'` |
| **Role filter** | `role IN ('owner', 'council')` |
| **Unit filter** | `unit_no IS NOT NULL` AND `trim(unit_no) <> ''` |
| **Ranking rule** | One eligible voter per normalized unit: partition by `(property_id, lower(trim(unit_no)))`; order `council` before `owner`, then `user_id`; rank `1` wins |
| **User identity** | `property_members.user_id` |
| **Role at freeze** | `property_members.role` as stored |
| **Source timestamp** | Read occurs inside the active atomic work envelope — logically one freeze boundary |

IU-2.1 **shall not** invoke legacy `freeze_owner_vote_snapshot` RPC. E-02 orchestration **replicates the PEC eligibility logic** inside the Freeze Engine envelope without adopting legacy DELETE-and-rebuild or `snapshot_frozen_at` side effects (Phase 3 owns meeting freeze marker).

IU-2.1 **shall not** invent a new eligibility policy. The PEC reflects approved production behavior documented in RC010-B and aligns with CDR-001 MODEL B constitutional target.

### 5.2 Source contract elements

| Element | Authority |
|---------|-----------|
| Source table / contract | `property_members` — PEC |
| Meeting filter | `FreezeContext.meetingId` + property binding |
| Property filter | `FreezeContext.propertyId` |
| Eligible-member criteria | PEC §5.1 filters + unit ranking |
| User identity mapping | `property_members.user_id` |
| Unit identity mapping | `property_members.unit_no` — normalized as `trim(unit_no)` for ranking; stored as source value |
| Role mapping | `property_members.role` |
| Eligibility flag derivation | `is_eligible = true` for rank-1 rows only; rank > 1 excluded from materialization |
| Source timestamp semantics | Single envelope freeze instant — see §15 |

## 6. Freeze-time capture model

The materialized Voter Snapshot **must** represent **one logical freeze boundary**.

| Rule | Requirement |
|------|-------------|
| Single read context | All source rows evaluated under the same transaction context |
| No cross-attempt mixing | Rows from different freeze attempts **shall not** be combined |
| Correlation | All rows: same `meetingId` · same `propertyId` · same `freezeEventId` · same attempt identity · same atomic work envelope |

## 8. Source → target mapping

Deterministic mapping contract:

| Source | Target | Transformation | Nullable | Validation | Failure |
|--------|--------|----------------|----------|------------|---------|
| `FreezeContext.meetingId` | `meeting_id` | Direct | NO | UUID match meeting | `CORRELATION_FAILURE` |
| `FreezeContext.propertyId` | `property_id` | Direct | NO | UUID match property | `CORRELATION_FAILURE` |
| `FreezeContext.freezeEventId` | `freeze_event_id` | Direct | NO | UUID present | `CORRELATION_FAILURE` |
| PEC rank-1 `user_id` | `user_id` | Direct | NO | Valid UUID | `INVALID_SOURCE` |
| PEC rank-1 `unit_no` | `unit_no` | `trim` preserved for storage | NO | Non-empty after trim | `INVALID_SOURCE` |
| PEC rank-1 `role` | `role` | Direct | NO | `owner` or `council` | `INVALID_SOURCE` |
| PEC rank-1 winner | `is_eligible` | Constant `true` | NO | Always true | — |
| Envelope freeze instant | `frozen_at` | Uniform timestamp | NO | Same value all rows | `TRANSACTION_FAILURE` |
| Insert instant | `created_at` | Orchestration timestamp | NO | Per row | `PERSISTENCE_FAILURE` |
| Orchestration | `id` | New UUID v4 | NO | Unique within batch | `DUPLICATE_FAILURE` |

**Note:** Legacy production RPC materializes **only** rank-1 eligible rows (`is_eligible = true`). IU-2.1 **matches** that contract — ineligible ranked-out members are **not** persisted.

## 9. Identity rules

| Rule | Requirement |
|------|-------------|
| Row identity | New UUID (`gen_random_uuid()` equivalent) per materialized row |
| User identity | Must be valid `property_members.user_id` for rank-1 row |
| Unit normalization | Ranking uses `lower(trim(unit_no))`; stored `unit_no` preserves source trimmed value |
| Duplicate detection | See §10 |
| Null `user_id` | **Not permitted** — source row excluded; if rank-1 row lacks user → `INVALID_SOURCE` |
| Null / empty `unit_no` | **Not permitted** for materialized rows — filtered at source |

No row **shall** be silently merged or duplicated.

---

## 10. Duplicate handling

### 10.1 Duplicate dimensions

| Dimension | Classification |
|-----------|----------------|
| Same `freeze_event_id` + same `user_id` | **Identity collision** — fail closed |
| Same `freeze_event_id` + same normalized `unit_no` | **Identity collision** — fail closed |
| Same meeting + legacy row (`freeze_event_id IS NULL`) + new event-linked row | **Legacy coexistence** — permitted; IU-2.1 does not modify legacy rows |
| Multiple units for same user | **Valid** if distinct normalized units (unusual but not blocked unless duplicate dimension hit) |
| Rank > 1 same unit | **Not materialized** — excluded by PEC ranking |

### 10.2 Behavior

| Case | Action |
|------|--------|
| Valid multiple rows | One row per distinct normalized unit |
| Data-source duplicate (two rank-1 for same unit) | **DUPLICATE_FAILURE** |
| Identity collision in staged batch | **DUPLICATE_FAILURE** |
| Ambiguous duplicate | **FAIL CLOSED** — no silent deduplication |

## 11. Eligibility semantics

IU-2.1 materializes **freeze-time eligibility state** only.

| Field | Semantics |
|-------|-----------|
| `is_eligible` | Records that this row is the ranked eligible voter for the unit at freeze instant |

IU-2.1 **shall not** perform E-03 ballot authorization.

IU-2.1 **shall not:** issue ballots · open voting · enforce ballot submission · calculate vote outcomes

E-03 later consumes frozen voter state for voting authorization.

## 12. Correlation contract

Every materialized row **shall** reference the authoritative Freeze Event.

| Required equality |
|-------------------|
| `row.freeze_event_id = FreezeContext.freezeEventId` |
| `row.meeting_id = FreezeContext.meetingId` |
| `row.property_id = FreezeContext.propertyId` |

**Prohibited:** Cross-event · cross-meeting · cross-property voter rows

Correlation mismatch **shall** fail materialization → `CORRELATION_FAILURE`

## 13. Immutability interaction

E-01 event-linked immutability applies when `freeze_event_id IS NOT NULL` (trigger `trg_owner_vote_voter_snapshot_event_linked_immutable` per E-01 IU-2.2).

| Rule | Requirement |
|------|-------------|
| IU-2.1 rows | **Always** event-linked — `freeze_event_id` set |
| Post-materialization mutation | **Prohibited** — no UPDATE/DELETE after staging within committed envelope |
| Post-commit correction | **E-06** only |

IU-2.1 **shall not** depend on UPDATE after materialization, DELETE + rebuild after commit, or post-commit mutation.

---

## 14. Legacy coexistence

Existing production legacy rows may have `freeze_event_id IS NULL` (44 rows per E-01 acceptance evidence).

IU-2.1 **shall not:**

| Prohibition |
|-------------|
| Modify legacy rows |
| Delete legacy rows |
| Rebuild legacy meetings |
| Reinterpret legacy history |

New E-02 materialization **shall** create **event-linked rows only** for the current authorized Freeze Event.

**Legacy isolation rule:** IU-2.1 writes **INSERT** scoped to `freeze_event_id = FreezeContext.freezeEventId` only. No `DELETE FROM owner_vote_voter_snapshot WHERE meeting_id = …` (legacy RPC pattern) inside E-02 envelope.

## 15. Materialization algorithm

```
Receive authoritative FreezeContext
        ↓
Verify MATERIALIZATION_READY + entry contract (§4)
        ↓
Load authoritative eligibility source (PEC / property_members)
        ↓
Validate source completeness (meeting exists, property binding)
        ↓
Apply PEC ranking — derive rank-1 eligible set
        ↓
Map source rows → target contract (§8)
        ↓
Validate identities (§9)
        ↓
Validate duplicates (§10)
        ↓
Validate correlation (§12)
        ↓
Stage Voter Snapshot rows inside atomic envelope
        ↓
Verify row-set completeness (§16)
        ↓
Return IU-2.1 materialization result (§17)
```

**No independent commit.**

### 15.1 Freeze instant (`frozen_at`)

**VQ-007 resolution:** One orchestration-supplied **freeze boundary instant** (`freezeBoundaryAt`) is captured at envelope materialization start and applied **uniformly** to all rows in the batch. Per-row `now()` drift is **prohibited**.

`created_at` may equal `frozen_at` or reflect insert instant — both within the same envelope; `frozen_at` **shall** be identical across all rows in the set.

---

## 16. Completeness contract

IU-2.1 is successful **only** when the required voter row set is **completely** materialized inside the envelope.

Completeness **shall** verify:

| Check |
|-------|
| Source rows evaluated |
| Required rank-1 rows represented |
| All rows correlated |
| All identities valid |
| No unresolved duplicates |
| Eligible counts internally consistent |

If completeness fails: IU-2.1 reports failure → Phase 1 Rollback Contract applies. No partial Voter Snapshot **may** survive the failed attempt.

**MI-3 note:** IU-2.1 contributes voter-domain completeness only. Full Phase 2 **COMMIT_READY** requires IU-2.2 + IU-2.3 + aggregate verification.

---

## 17. Materialization result contract

IU-2.1 **shall** return **one deterministic result**.

### 17.1 Outcomes

| Decision | Meaning |
|----------|---------|
| **MATERIALIZED** | Complete voter row set staged inside envelope |
| **INVALID_SOURCE** | Source missing, inconsistent, or failed validation |
| **CORRELATION_FAILURE** | Context/row correlation mismatch |
| **DUPLICATE_FAILURE** | Identity collision or ambiguous duplicate |
| **PERSISTENCE_FAILURE** | Staging/write error |
| **TRANSACTION_FAILURE** | Envelope or ownership failure |

### 17.2 Result payload

| Field | Required |
|-------|----------|
| `decision` | Always |
| `freezeEventId` | Always |
| `meetingId` | Always |
| `propertyId` | Always |
| `sourceRowCount` | Candidate count pre-ranking |
| `materializedRowCount` | Staged row count |
| `eligibleRowCount` | Count where `is_eligible = true` |
| `failureReason` | When decision ≠ **MATERIALIZED** |

**No partial-success outcome** is permitted.

## 18. Count / reconciliation model

| Count | Definition |
|-------|------------|
| `sourceCandidateCount` | Active owner/council members with non-empty `unit_no` for property (pre-ranking) |
| `sourceEligibleCount` | Rank-1 rows after PEC unit ranking |
| `sourceIneligibleCount` | `sourceCandidateCount - sourceEligibleCount` (informational — not persisted) |
| `materializedTotalCount` | Rows staged for `freezeEventId` |
| `materializedEligibleCount` | Staged rows with `is_eligible = true` |
| `rejectedErrorCount` | Rows failing validation (should be 0 on success) |

### 18.1 Reconciliation rules (VQ-006)

| Rule | Requirement |
|------|-------------|
| R-1 | `materializedTotalCount = sourceEligibleCount` |
| R-2 | `materializedEligibleCount = materializedTotalCount` |
| R-3 | `rejectedErrorCount = 0` on **MATERIALIZED** |
| R-4 | No unexplained count drift |

Design Review **shall** verify reconciliation rules. Engineering Implementation Review **shall** verify runtime counts.

## 20. Rollback interaction

IU-2.1 does **not** own an independent rollback transaction.

IU-2.1 **shall** propagate failure to the authoritative transaction owner. Phase 1 Rollback Contract governs the envelope.

After rollback: no IU-2.1 event-linked rows from the failed attempt **may** remain durable.

| Condition | Behavior |
