## 6. Section findings summary

### PEC fidelity

PEC (RC010-B §7.3) correctly consumed. E-02 replicates eligibility logic without legacy RPC invocation, meeting-level DELETE, or Phase 3 freeze marker side effects.

### Eligibility / role

Rank-1 per normalized unit with council-over-owner ranking. `role` preserved from winning source row as freeze-time evidence — not ballot authorization.

### Freeze-time consistency

Single `freezeBoundaryAt` applied uniformly; no per-row timestamp drift.

### Mapping / identity

Full E-01 target contract mapped deterministically with explicit failure outcomes per field.

### Duplicate contract

**Design note:** Implementation §10.1 lists `freeze_event_id + user_id` as identity collision while also permitting multiple units for the same user — **internal contradiction**. Resolved authoritatively at this review (**RA-2.1-001**): invalid duplicate dimension is **unit-scoped** (`freeze_event_id` + normalized `unit_no`), aligned with PEC one-row-per-unit semantics and production `uq_owner_vote_snapshot_meeting_unit` intent (meeting-scoped legacy analogue).

### Count reconciliation

`sourceEligible = materializedTotal = materializedEligible`; legacy rows excluded; drift fails closed.

### Completeness / correlation / immutability / legacy

Complete rank-1 set required for MATERIALIZED. Strict event/meeting/property correlation. Event-linked immutability. Legacy INSERT-only isolation.

### Algorithm / result / failure

Deterministic ordered algorithm; six terminal outcomes; rollback via Phase 1 owner; no idempotent-path execution.

| C-3 | **`created_at` vs `frozen_at`:** `frozen_at` = legal freeze instant (`freezeBoundaryAt`); `created_at` = persistence metadata — must not be conflated in orchestration or UI |
| C-4 | **Event-linked uniqueness:** E-01 repo migrations do not yet define `freeze_event_id + unit` unique index — duplicate enforcement is orchestration contract at design level; EIR verifies constraint behavior when implemented |
