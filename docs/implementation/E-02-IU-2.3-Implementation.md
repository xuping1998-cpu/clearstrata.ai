## 1. Purpose

Define the **implementation design** for **IU-2.3 — Frozen Motion Materialization**.

IU-2.3 **shall** materialize the complete set of freeze-time Frozen Motions beneath the authoritative `resolutionSnapshotId` established by IU-2.2.

IU-2.3 **shall** consume the certified Phase 1 Freeze Transaction Foundation Baseline, IU-2.1 Voter Snapshot Materialization Baseline, and IU-2.2 Resolution Snapshot Materialization Baseline.

IU-2.3 **shall** complete the remaining Phase 2 materialization domain and determine whether the full Phase 2 snapshot set is eligible to transition to **COMMIT_READY**.

IU-2.3 **shall not:** perform final atomic commit · write the meeting freeze marker · perform phase transition · write primary audit · authorize ballots · execute voting · create an alternate Resolution Snapshot parent.

This document implements [`E-02-Phase-2-Implementation-Plan.md`](E-02-Phase-2-Implementation-Plan.md) §IU-2.3 and **shall not redefine** architecture decisions in [`E-02-Architecture.md`](E-02-Architecture.md).

## 3. Objective

Materialize **one complete, correlated set** of Frozen Motions for the authoritative Resolution Snapshot.

The result **shall** preserve:

| Preserved element |
|-------------------|
| Source resolution identity |
| Source agenda identity where applicable |
| Source formal-resolution version where applicable |
| Motion title |
| Motion description / text |
| Vote threshold; vote method where defined |
| Deterministic ordering |
| Same Freeze Event · meeting · property |
| Same atomic work envelope |
| Same `freezeBoundaryAt` |

When IU-2.3 succeeds **and** Phase 2 aggregate completeness verification passes, the Phase 2 snapshot domain **shall** be complete enough to permit **COMMIT_READY** — but **not** **COMMITTED**.

## 4. Entry contract

IU-2.3 may begin **only** when **all** conditions hold:

| Condition | Requirement |
|-----------|-------------|
| IU-2.1 result | **MATERIALIZED** |
| IU-2.2 result | **RESOLUTION_MATERIALIZED** |
| `resolutionSnapshotId` | Exists on `FreezeContext` |
| `freezeEventId` | Exists |
| `meetingId` | Exists |
| `propertyId` | Exists |
| `freezeBoundaryAt` | Exists |
| Atomic work envelope | Active — same envelope as IU-2.1 / IU-2.2 |
| Transaction state | Materialization-active |

If any required condition is missing or inconsistent: **FAIL CLOSED**.

IU-2.3 **shall not:** regenerate voter materialization · recreate Resolution Snapshot header · replace `resolutionSnapshotId` · open an independent transaction · repair Phase 1 state.

## 5. Authoritative motion source

### 5.1 Source authority

IU-2.3 **shall** use the live Resolution source authority established by IU-2.2:

**`public.owner_vote_resolutions`**

filtered for the authoritative meeting.

The source motion set **shall** be the **same qualifying resolution set** used to establish IU-2.2 instrument completeness (IU-2.2 Completion §10):

| Filter | Rule |
|--------|------|
| Meeting | `meeting_id = FreezeContext.meetingId` |
| Title validity | Non-empty `title` after trim |
| Property binding | Verified via meeting binding already validated in IU-2.2 |

IU-2.3 **shall not** select a competing motion source.

### 5.2 Supporting provenance inputs

Supporting fields **may** be read from related production structures **only** as provenance inputs — not as alternate authority:

| Supporting source | Provenance use |
|-------------------|----------------|
| `meeting_agenda_items` | `source_agenda_item_id` · `source_formal_resolution_version` |
| Council meeting binding | Resolve agenda rows via [`resolveCouncilMeetingIdForOwnerVoteTitle`](../../src/features/meetings/ownerVotingCouncil.ts) pattern |

Agenda linkage **shall not** override `owner_vote_resolutions` as motion content authority.

## 6. Motion set cardinality

The authoritative model is:

```
N qualifying owner_vote_resolutions
        ↓
1 Resolution Snapshot header (IU-2.2)
        ↓
N owner_vote_frozen_motions
```

| Rule | Requirement |
|------|-------------|
| One source row | One Frozen Motion (1:1 source coverage) |
| No silent omission | Every qualifying source row materialized |
| No unauthorized duplication | One source row → at most one Frozen Motion |
| Header multiplicity | **Prohibited** — RI-5 / IU-2.2 baseline preserved |

| Live ID prohibition | Frozen `id` **shall not** equal `owner_vote_resolutions.id` |

| Distinction | **Frozen Identity ≠ Live Source Identity** (E-01 IU-3.1) |

## 9. Parent binding contract

Every Frozen Motion **shall** bind to IU-2.2 parent:

```
Frozen Motion.resolution_snapshot_id = FreezeContext.resolutionSnapshotId
```

IU-2.3 **shall not:** create a second Resolution Snapshot · infer a different parent per motion · create cross-header motion sets.

All Frozen Motions for one freeze attempt belong beneath the **same** Resolution Snapshot header.

---

## 10. Freeze Event correlation

Every Frozen Motion **shall** satisfy:

| Required equality |
|-------------------|
| `row.freeze_event_id = FreezeContext.freezeEventId` |
| `row.owner_vote_meeting_id = FreezeContext.meetingId` |
| `row.property_id = FreezeContext.propertyId` |

Shared with IU-2.1 / IU-2.2: same attempt identity · transaction ownership · atomic envelope · `freezeBoundaryAt`.

Cross-event motion state is **prohibited**.

---

## 11. Freeze-time consistency

IU-2.3 **shall** use exactly the same **`freezeBoundaryAt`** as IU-2.1 and IU-2.2.

Every Frozen Motion:

```
frozen_at = FreezeContext.freezeBoundaryAt
```

Per-row timestamp generation for `frozen_at` is **prohibited**.

Therefore Voter Snapshot = Resolution Snapshot = Frozen Motions with respect to the **logical freeze boundary**.

`created_at` remains persistence metadata only.

## 12. Source → target mapping

Deterministic mapping contract for each qualifying `owner_vote_resolutions` row:

| Source | Target | Transformation | Nullable | Validation | Failure |
|--------|--------|----------------|----------|------------|---------|
| Orchestration | `id` | New UUID v4 | NO | Unique within batch | **DUPLICATE_MOTION_FAILURE** |
| `FreezeContext.resolutionSnapshotId` | `resolution_snapshot_id` | Direct | NO | UUID present | **CORRELATION_FAILURE** |
| `FreezeContext.freezeEventId` | `freeze_event_id` | Direct | NO | UUID match | **CORRELATION_FAILURE** |
| `FreezeContext.meetingId` | `owner_vote_meeting_id` | Direct | NO | UUID match | **CORRELATION_FAILURE** |
| `FreezeContext.propertyId` | `property_id` | Direct | NO | UUID match | **CORRELATION_FAILURE** |
| Source `display_order` | `display_order` | See §15 | NO | Integer ≥ 0 unique per snapshot | **DUPLICATE_MOTION_FAILURE** |
| Source `title` | `title` | `trim` preserved | NO | Non-empty after trim | **INVALID_MOTION_CONTENT** |
| Source `description` | `description` | Direct / null | YES | — | **INVALID_MOTION_CONTENT** if required field invalid |
| Source `threshold` | `threshold` | `trim` as text | NO | Non-empty after trim | **INVALID_MOTION_CONTENT** |
| Source vote method | `vote_method` | Map if authoritative source exists; else NULL | YES | — | — |
| Resolved agenda item | `source_agenda_item_id` | UUID when resolved | YES | Valid UUID if present | **INVALID_SOURCE** |
| Source `id` | `source_resolution_id` | Direct UUID | NO for qualifying rows | Valid UUID | **INVALID_SOURCE** |
| Resolved agenda `formal_resolution_version` | `source_formal_resolution_version` | Integer when resolved | YES | — | — |
| Envelope `freezeBoundaryAt` | `frozen_at` | Direct uniform value | NO | Same as IU-2.1 / IU-2.2 | **TRANSACTION_FAILURE** |
| Insert instant | `created_at` | Orchestration timestamp | NO | Per row | **PERSISTENCE_FAILURE** |

### 12.1 Vote method mapping note

Production `owner_vote_resolutions` has **no** `vote_method` column in current repository usage ([`api.ts`](../../src/features/meetings/api.ts) selects `id, title, threshold, display_order` only).

Therefore **`vote_method` defaults to NULL** at materialization unless Design Review identifies an authoritative production source field. E-01 schema permits NULL (*nullable until E-02 maps source*).

## 13. Source provenance baseline

IU-2.3 is the **authoritative materialization layer** for motion-level provenance.

| Field | Authority |
|-------|-----------|
| `source_resolution_id` | **Mandatory** for qualifying rows — `owner_vote_resolutions.id` |
| `source_agenda_item_id` | **Optional** — resolved when agenda linkage evidence exists |
| `source_formal_resolution_version` | **Optional** — from matched `meeting_agenda_items.formal_resolution_version` |

Provenance **shall not** be reconstructed after commit.

### 13.1 Agenda linkage resolution (proposed)

When council meeting binding is resolvable, IU-2.3 **may** match agenda items to source resolutions using the production pattern in [`findOwnerVoteResolutionForAgenda`](../../src/features/meetings/ownerVotingCouncil.ts):

1. Prefer `display_order === sort_order`
2. Else title match (zh/en vs resolution title)

If no unique agenda match: `source_agenda_item_id` and `source_formal_resolution_version` remain **NULL** — permitted by E-01 legacy path. This **shall not** block materialization when motion content fields are valid.

## 14. Motion content baseline

For every qualifying source Resolution row, IU-2.3 **shall** freeze all E-01-required content fields:

| Frozen field | Source |
|--------------|--------|
| `title` | `owner_vote_resolutions.title` |
| `description` | `owner_vote_resolutions.description` (nullable) |
| `threshold` | `owner_vote_resolutions.threshold` |
| `vote_method` | NULL unless authoritative source identified |
| `display_order` | §15 |

IU-2.3 **shall not** silently omit an E-01-authorized motion field required by NOT NULL constraints (`title`, `threshold`, `display_order`).

---

## 15. Ordering contract

### 15.1 Authoritative ordering source

Primary ordering authority: **`owner_vote_resolutions.display_order`** ascending.

This matches production read pattern ([`fetchOwnerVoteMeetingMetaForCouncilMeeting`](../../src/features/meetings/api.ts): `.order('display_order', { ascending: true })`).

### 15.2 Null / tie behavior

| Case | Behavior |
|------|----------|
| `display_order` present | Use integer value |
| `display_order` null | Assign deterministic sequence after ordered rows using stable tie-break: `owner_vote_resolutions.id` ascending |
| Duplicate `display_order` within snapshot | **DUPLICATE_MOTION_FAILURE** — unique index `(resolution_snapshot_id, display_order)` |

IU-2.3 **shall not** invent arbitrary ordering unrelated to source evidence.

---

## 16. Duplicate contract

### 16.1 Invalid duplicates

| Condition | Classification |
|-----------|----------------|
| Same `resolution_snapshot_id` + same `source_resolution_id` (non-null) | **Invalid** — **DUPLICATE_MOTION_FAILURE** |
| Same `resolution_snapshot_id` + same `display_order` | **Invalid** — **DUPLICATE_MOTION_FAILURE** (persistence unique index) |
| One source row → two Frozen Motions | **Invalid** — fail closed |

### 16.2 Valid multiplicity

| Condition | Classification |
|-----------|----------------|
| N distinct source resolutions → N Frozen Motions | **Valid** |
| Same user across units (voter domain) | **Not applicable** — motion domain |

No silent deduplication.

## 17. Motion completeness contract

IU-2.3 local success requires:

```
sourceMotionCount = frozenMotionCount
rejectedCount = 0
```

Where **`sourceMotionCount`** = count of qualifying `owner_vote_resolutions` rows (same qualification as IU-2.2).

Additionally:

| Requirement |
|-------------|
| All rows correlated to Freeze Event / parent / meeting / property |
| Required source provenance represented (`source_resolution_id` on every row) |
| Required motion fields mapped successfully |
| Duplicate count = 0 |
| No partial batch success |

Any unexplained drift: **FAIL CLOSED**.

## 18. Phase 2 aggregate completeness

IU-2.3 is the **final** Phase 2 materialization unit.

After successful IU-2.3 local materialization, **Phase 2 Aggregate Completeness Verification** **shall** confirm:

| Gate | Requirement |
|------|-------------|
| IU-2.1 | **MATERIALIZED** |
| IU-2.2 | **RESOLUTION_MATERIALIZED** |
| IU-2.3 | **MOTIONS_MATERIALIZED** |
| Voter completeness | IU-2.1 count reconciliation satisfied |
| Resolution header completeness | IU-2.2 one-to-one binding satisfied |
| Motion completeness | IU-2.3 count reconciliation satisfied |
| Correlation | Same `freezeEventId` across all artifacts |
| Freeze boundary | Same `freezeBoundaryAt` across all artifacts |
| Envelope | Same atomic work envelope active |

Only after **all** aggregate gates pass may orchestration signal **COMMIT_READY** per Phase 2 Plan §20.

## 19. COMMIT_READY ownership

| State | Meaning | Owner |
|-------|---------|-------|
| **MOTIONS_MATERIALIZED** | IU-2.3 local success | IU-2.3 |
| **Phase 2 aggregate verification** | All Phase 2 gates pass | Phase 2 orchestration |

Therefore:

```
MOTIONS_MATERIALIZED ≠ COMMIT_READY ≠ COMMITTED
```

IU-2.3 **shall not** equate local success with **COMMIT_READY** without aggregate verification.

## 21. Materialization algorithm

```
Receive authoritative FreezeContext (post IU-2.2 RESOLUTION_MATERIALIZED)
        ↓
Verify entry contract (§4)
        ↓
Verify resolutionSnapshotId present
        ↓
Verify active atomic envelope
        ↓
Load qualifying owner_vote_resolutions set (§5 — same as IU-2.2 qualification)
        ↓
Validate sourceMotionCount >= 1 (§23)
        ↓
Determine authoritative ordering (§15)
        ↓
For each source Resolution row:
  · generate Frozen Motion id
  · map content fields (§12)
  · map provenance (§13)
  · bind resolutionSnapshotId
  · bind Freeze Event / meeting / property
  · assign same freezeBoundaryAt
  · validate required fields
        ↓
Validate duplicate contract (§16)
        ↓
Stage all Frozen Motions inside same envelope
        ↓
Reconcile sourceMotionCount vs frozenMotionCount (§17)
        ↓
Verify parent / event correlation (§9–§10)
        ↓
Return MOTIONS_MATERIALIZED
        ↓
Phase 2 Aggregate Completeness Verification (§18)
        ↓
If all Phase 2 gates pass → COMMIT_READY
```

**No independent commit.**

## 22. Result contract

| Outcome | Meaning |
|---------|---------|
| **MOTIONS_MATERIALIZED** | IU-2.3 local materialization success |
| **INVALID_SOURCE** | Source or provenance validation failure |
| **MISSING_MOTION_SOURCE** | Zero qualifying source motions |
| **INVALID_MOTION_CONTENT** | Required content field invalid |
| **CORRELATION_FAILURE** | Parent / event / meeting / property mismatch |
| **DUPLICATE_MOTION_FAILURE** | Duplicate motion dimension hit |
| **PERSISTENCE_FAILURE** | Staging or persistence failure |
| **TRANSACTION_FAILURE** | Transaction envelope failure |

Only **MOTIONS_MATERIALIZED** means IU-2.3 local success.

No IU-2.3 local result means **COMMITTED**.

**COMMIT_READY** is emitted only by Phase 2 aggregate orchestration after §18 verification — not as an IU-2.3 local result code.

## 23. Zero-motion semantics

Given IU-2.2 requires **≥1** qualifying `owner_vote_resolutions` row, the authoritative model is:

```
sourceMotionCount >= 1
frozenMotionCount >= 1
```

| Condition | Outcome |
|-----------|---------|
| Zero qualifying source motions at IU-2.3 | **MISSING_MOTION_SOURCE** — fail closed |

Zero-motion freeze instruments are **not valid** under the certified IU-2.2 / IU-2.3 chain.

## 25. Rollback interaction

IU-2.3 **shall not** own an independent rollback transaction.

Any IU-2.3 failure propagates to the Phase 1 transaction owner.

Phase 1 rollback **must** remove the complete failed materialization attempt:

```
staged IU-2.1 voter rows
+ staged IU-2.2 Resolution Snapshot
+ staged IU-2.3 Frozen Motions
```

No durable partial Phase 2 snapshot domain may survive.

---

## 26. Idempotency interaction

Phase 1 remains authoritative.

| Phase 1 outcome | Phase 2 / IU-2.3 behavior |
|-----------------|----------------------------|
| **IDEMPOTENT RETURN** | Phase 2 does not execute |
| **RETRYABLE** | Phase 2 does not execute |

IU-2.3 **shall not:** independently rebuild committed motions · resolve transaction ownership · create alternative freeze attempt · silently replace committed motion state.

---

## 27. Immutability interaction

Frozen Motions participate in the E-01-certified immutability model (trigger `trg_owner_vote_frozen_motions_event_linked_immutable` per E-01 IU-3.2).

IU-2.3 **shall not** depend on post-materialization UPDATE, post-commit DELETE, DELETE + rebuild, silent motion replacement, or source-provenance rewriting after commit.

Post-commit correction remains **E-06** scope.
