## 7. Entry / early idempotency gate baseline

IU-3.3 **final commit path** requires:

| Condition | Requirement |
|-----------|-------------|
| IU-3.1 result | **COMMIT_PREPARED** |
| IU-3.2 result | **AUDIT_PREPARED** |
| Atomic Commit Set | **A – G** complete |
| Correlation | Same `freezeEventId` · `meetingId` · `propertyId` · attempt · envelope · `freezeBoundaryAt` |
| Ownership | Valid |
| Superseding committed primary | **None** (or resolved via idempotency gate) |
| Primary Audit persistence | Satisfied at **executable implementation time** only |

**Early idempotency gate** (before full commit path):

| Detection | Outcome |
|-----------|---------|
| Durable committed primary exists | **IDEMPOTENT_RETURN** |
| Active competing owner | **RETRYABLE** |
| Terminal rollback · no owner · no committed primary | **NEW_ATTEMPT_REQUIRED** — Phase 1 re-entry |

Any failure: **FAIL CLOSED**. No repair Phase 1/2/3.1/3.2 · no ownership stealing · no second transaction · no live reconstruction.

## 8. Idempotency outcome baseline

### 8.1 Locked decision model

```
Durable COMMITTED exists          → IDEMPOTENT_RETURN
No durable committed + active owner → RETRYABLE
No durable committed + no active owner + terminal rollback → NEW_ATTEMPT_REQUIRED
COMMIT_OUTCOME_UNCERTAIN          → DURABLE RECONCILIATION FIRST
```

**After reconciliation:**

| Reconciliation result | Outcome |
|-----------------------|---------|
| Committed durable evidence | **IDEMPOTENT_RETURN** |
| Not committed + active owner | **RETRYABLE** |
| Rolled back / no active owner | **NEW_ATTEMPT_REQUIRED** |

```
RETRYABLE ≠ NEW_ATTEMPT_REQUIRED
```

These outcomes **shall not** be collapsed.

### 8.2 IDEMPOTENT_RETURN

| Rule | Requirement |
|------|-------------|
| Return original committed `freezeEventId` | **Mandatory** |
| No rematerialization | **Prohibited** |
| No marker rewrite · no second audit · no second DB COMMIT | **Prohibited** |
| No `status` UPDATE · no live reconstruction | **Prohibited** |
| May return committed snapshot/audit ids from **durable evidence only** | **Permitted** |

### 8.3 RETRYABLE

| Rule | Requirement |
|------|-------------|
| Active authoritative competing owner | **Required** |
| No ownership stealing · no Phase 2/3 · no COMMIT | **Prohibited** |
| Non-terminal — caller may retry later | **Required** |

### 8.4 NEW_ATTEMPT_REQUIRED

| Rule | Requirement |
|------|-------------|
| No durable committed · no active owner · prior lifecycle terminal | **Required** |
| Phase 1 re-entry | **Required** |
| New attemptId · freezeEventId · primaryAuditId | **Required** |
| No resume **COMMIT_PREPARED** / **AUDIT_PREPARED** of old attempt | **Prohibited** |

---

## 9. RETRYABLE vs NEW_ATTEMPT_REQUIRED

| Dimension | **RETRYABLE** | **NEW_ATTEMPT_REQUIRED** |
|-----------|---------------|--------------------------|
| Committed primary exists | N/A — **IDEMPOTENT_RETURN** instead | No |
| Active owner exists | **Yes** | **No** |
| Prior attempt state | In-flight contention | Terminal rolled back / abandoned |
| Identity assignment | **None** durable | **New** full lifecycle |
| Re-entry point | Same reconciliation gate later | Phase 1 validation / transaction lifecycle |
| Terminal for caller | **No** | **Yes** for old identity |

```
RETRYABLE ≠ NEW_ATTEMPT_REQUIRED
RETRYABLE ≠ failure of committed state
RETRYABLE ≠ IDEMPOTENT_RETURN
```

## 15. Concurrency baseline

Same-meeting concurrent freeze attempts:

| Scenario | Resolution |
|----------|------------|
| Attempt A owns active freeze lifecycle | A may continue |
| Competing Attempt B | **RETRYABLE** |
| A later **COMMITTED** | B → **IDEMPOTENT_RETURN** |
| A rolls back | Next valid invocation → **NEW_ATTEMPT_REQUIRED** with new identities |

**Prohibited:** ownership stealing · dual primary · duplicate Primary Audit · second durable freeze commit · parallel competing materialization.

**Guards consumed:** Phase 1 ownership · `owner_vote_freeze_events_one_primary_per_meeting` · Primary Audit `UNIQUE(freeze_event_id)` (when implemented).

## 17. COMMIT_OUTCOME_UNCERTAIN baseline

**Scenario:** DB COMMIT requested → response/connection lost → caller cannot know result.

```
COMMIT_OUTCOME_UNCERTAIN → DURABLE RECONCILIATION FIRST
```

**Prohibited on timeout alone:**

| Prohibition |
|-------------|
| Immediately create new attempt |
| Immediately return **COMMITTED** |
| Infer rollback without durable evidence |

**Required example (semantic):**

```
DB COMMIT succeeds but ack lost
→ next invocation reconciles durable state
→ finds committed primary + A–G
→ IDEMPOTENT_RETURN
→ MUST NOT create second freeze
```

Never infer rollback merely because client acknowledgement was lost.
