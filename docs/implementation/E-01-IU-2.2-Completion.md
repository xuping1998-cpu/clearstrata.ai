## 3. Objective

Implement persistence-layer UPDATE and DELETE protection for `owner_vote_voter_snapshot` rows correlated to a Freeze Event (`freeze_event_id IS NOT NULL`), per Blueprint §9 / INV-1. Legacy rows without freeze-event linkage must continue to support the existing production DELETE + INSERT rebuild workflow.

## 5. Database Changes

- **Indexes / FKs / RLS:** Unchanged from IU-2.1
- **Mechanism:** `BEFORE UPDATE OR DELETE` row trigger with `WHEN (OLD.freeze_event_id IS NOT NULL)`

### Trigger / policy summary

| Object | Behavior |
|--------|----------|
| `owner_vote_voter_snapshot_event_linked_immutable()` | Raises exception on UPDATE or DELETE when invoked |
| `trg_owner_vote_voter_snapshot_event_linked_immutable` | Fires only when `OLD.freeze_event_id IS NOT NULL`; legacy NULL rows bypass trigger entirely |
| RLS policies | Not used — SECURITY DEFINER freeze RPC still subject to triggers (correct for immutability) |

**Not blocked:** INSERT (including legacy rebuild inserts); UPDATE/DELETE where `OLD.freeze_event_id IS NULL`; UPDATE that sets `freeze_event_id` on a previously unlinked row (E-02 population path).

### Staging verification SQL (run after migration apply)

Requires fixture meeting, property, and freeze event. Replace placeholder UUIDs.

```sql
-- Setup (minimal fixture)
-- INSERT owner_vote_meetings / properties as needed
-- INSERT INTO owner_vote_freeze_events (...) RETURNING id AS fe_id;

-- 1) Legacy row: DELETE + INSERT must succeed
INSERT INTO owner_vote_voter_snapshot (
  meeting_id, property_id, unit_no, user_id, role, is_eligible
) VALUES (
  :meeting_id, :property_id, '101', :user_id, 'owner', true
);

DELETE FROM owner_vote_voter_snapshot
WHERE meeting_id = :meeting_id AND freeze_event_id IS NULL;
-- Expected: success

-- 2) Event-linked row: UPDATE must fail
INSERT INTO owner_vote_voter_snapshot (
  meeting_id, property_id, unit_no, user_id, role, is_eligible, freeze_event_id
) VALUES (
  :meeting_id, :property_id, '102', :user_id, 'owner', true, :fe_id
);

UPDATE owner_vote_voter_snapshot
SET unit_no = '102B'
WHERE freeze_event_id = :fe_id;
-- Expected: ERROR — Event-linked owner_vote_voter_snapshot rows are immutable (E-01 INV-1)

-- 3) Event-linked row: DELETE must fail
DELETE FROM owner_vote_voter_snapshot
WHERE freeze_event_id = :fe_id;
-- Expected: ERROR — Event-linked owner_vote_voter_snapshot rows cannot be deleted (E-01 INV-1)

-- 4) Link-on-update (E-02 path): NULL -> non-NULL must succeed
INSERT INTO owner_vote_voter_snapshot (
  meeting_id, property_id, unit_no, user_id, role, is_eligible
) VALUES (
  :meeting_id, :property_id, '103', :user_id, 'owner', true
) RETURNING id AS legacy_id;

UPDATE owner_vote_voter_snapshot
SET freeze_event_id = :fe_id
WHERE id = :legacy_id;
-- Expected: success (OLD.freeze_event_id was NULL)
```

## 8. Backward Compatibility

**Fully preserved for current production.**

All existing voter snapshot rows have `freeze_event_id IS NULL`; the trigger `WHEN` clause does not activate, so `freeze_owner_vote_snapshot` DELETE + INSERT rebuild behavior is unchanged. No RPC or application code was modified. After E-02 populates event-linked rows, those specific rows become immutable; re-freeze orchestration must follow E-02/E-06 design (not IU-2.2 scope).
