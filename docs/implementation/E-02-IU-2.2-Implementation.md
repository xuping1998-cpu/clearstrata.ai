## 1. Purpose

Define the **implementation design** for **IU-2.2 — Resolution Snapshot Materialization**.

IU-2.2 **shall** materialize **one authoritative Resolution Snapshot** for the current Freeze Event inside the existing Phase 1 atomic work envelope.

IU-2.2 **shall** establish the immutable instrument-level parent identity required by **IU-2.3 — Frozen Motion Materialization**.

IU-2.2 **shall not:** materialize Frozen Motions · perform final Phase 2 completeness · emit **COMMIT_READY** · perform Phase 3 final commit · write primary audit · or alter Voter Snapshot semantics.

This document implements [`E-02-Phase-2-Implementation-Plan.md`](E-02-Phase-2-Implementation-Plan.md) §IU-2.2 and **shall not redefine** architecture decisions in [`E-02-Architecture.md`](E-02-Architecture.md).

## 3. Objective

Materialize **exactly one** freeze-time Resolution Snapshot header for the authoritative Freeze Event.

The result **shall:**

| Requirement | Detail |
|-------------|--------|
| Represent the meeting's freeze-time resolution instrument | Instrument **header** — container identity only |
| Bind to the same Freeze Event as IU-2.1 | Shared `freezeEventId` |
| Bind to the same meeting and property | Shared `meetingId` · `propertyId` |
| Preserve the E-01 Resolution Snapshot identity contract | Stable generated `id` · 1:1 with Freeze Event |
| Establish parent identity for IU-2.3 | `resolutionSnapshotId` hand-off |
| Remain inside the same atomic work envelope | No independent commit |

| Condition | Requirement |
|-----------|-------------|
| IU-2.1 result | **MATERIALIZED** |
| `FreezeContext` | Exists and unchanged from IU-2.1 |
| `freezeEventId` | Exists |

## 5. Live resolution authority

### 5.1 Source authority model

IU-2.2 **shall** identify **one authoritative live source contract** for the freeze-time resolution instrument. The Resolution Snapshot **header** is a correlation container; motion **content** belongs to IU-2.3.

The design identifies **two cooperating source layers** — not alternative policies:

| Layer | Source | Role |
|-------|--------|------|
| **Meeting binding authority** | `public.owner_vote_meetings` | Confirms owner-vote session exists; verifies meeting ↔ property binding |
| **Instrument completeness authority** | `public.owner_vote_resolutions` | Confirms meeting-owned formal resolution instrument exists at freeze instant |

This aligns with [`E-01-Implementation-Plan.md`](E-01-Implementation-Plan.md) Phase 3 deliverables: *materialization reads from meeting-owned formal resolutions (`owner_vote_resolutions` + agenda linkage) at freeze instant* — E-02 performs materialization; E-01 defines schema and identity only.

IU-2.2 **shall not** invent a new resolution-authoring policy. RC010-A Decision **A** preserves meeting-owned pre-freeze formal resolution authority.

### 5.2 Meeting binding authority

| Field | Definition |
|-------|------------|
| **Source relation** | `public.owner_vote_meetings` |
| **Selection rule** | Row where `id = FreezeContext.meetingId` |
| **Property binding** | `owner_vote_meetings.property_id = FreezeContext.propertyId` |
| **Failure** | Missing row or property mismatch → **CORRELATION_FAILURE** |

### 5.3 Instrument completeness authority

| Field | Definition |
|-------|------------|
| **Source relation** | `public.owner_vote_resolutions` |
| **Meeting filter** | `meeting_id = FreezeContext.meetingId` |
| **Completeness rule** | At least **one** formal resolution row must exist for the meeting at freeze instant |
| **Row validity** | Each candidate row **shall** have non-empty `title` after trim |
| **Ordering evidence** | `display_order` read for completeness validation only — IU-2.3 materializes ordered motions |
| **Agenda linkage** | Optional at header stage; `meeting_agenda_items` linkage validated during IU-2.3 source binding where required by E-01 |

**Instrument selection rule:** The meeting's formal resolution **set** (N rows in `owner_vote_resolutions`) constitutes **one** logical instrument. IU-2.2 creates **exactly one header** for that set — **not** one header per resolution row (**RI-5**).

### 5.4 Rejected source families (for header authority)

| Source family | Classification |
|---------------|----------------|
| `community_resolutions` | **Not authoritative** for IU-2.2 header — legacy read-only; not live authoring source per RC010 |
| `meeting_agenda_items` alone | **Insufficient** for header — agenda rows are authoring input; live instrument projection is `owner_vote_resolutions` |
| `owner_vote_voter_snapshot` | **Wrong domain** — voter eligibility only |
| Live ballot rows | **Out of scope** — post-freeze consumption |

If repository evidence later identifies a competing authoritative source, **STOP** — resolve through Design Review before Completion. Do not guess.

### 5.5 Source contract elements

| Element | Authority |
|---------|-----------|
| Source table / contract | `owner_vote_meetings` + `owner_vote_resolutions` |
| Meeting filter | `FreezeContext.meetingId` |
| Property filter | `FreezeContext.propertyId` |
| Instrument selection | One header per Freeze Event regardless of N resolution rows |
| Formal-resolution eligibility | ≥ 1 valid `owner_vote_resolutions` row |
| Source identity at header | **None** — E-01 schema has no header-level source columns |
| Source version semantics | Deferred to IU-2.3 frozen motion bindings |
| Freeze-time completeness | Meeting binding + ≥ 1 valid resolution row |

## 8. Resolution Snapshot identity

### 8.1 Stable header identity

| Rule | Requirement |
|------|-------------|
| **Primary identity** | New UUID (`gen_random_uuid()` equivalent) assigned at materialization |
| **Stability** | `id` is the permanent frozen instrument-header identity for IU-2.3 and future ballot binding |
| **Live ID prohibition** | `id` **shall not** be copied from `owner_vote_resolutions.id` — live resolution rows remain mutable projections |
| **Parent role** | `resolutionSnapshotId` (= `id`) is the mandatory parent for all Frozen Motions in IU-2.3 |

### 8.2 Correlation identity bindings

| Binding | Source |
|---------|--------|
| `freeze_event_id` | `FreezeContext.freezeEventId` |
| `owner_vote_meeting_id` | `FreezeContext.meetingId` |
| `property_id` | `FreezeContext.propertyId` |

### 8.3 Retry behavior

| Case | Behavior |
|------|----------|
| Phase 1 **IDEMPOTENT RETURN** | IU-2.2 does not execute — committed primary already exists |
| Phase 1 **RETRYABLE** | IU-2.2 does not execute — no partial durable state |
| In-envelope retry after rollback | New attempt may assign new `resolutionSnapshotId` with new `freezeEventId` — prior rolled-back rows must not survive |

### 8.4 Duplicate behavior

| Condition | Outcome |
|-----------|---------|
| Same `freeze_event_id` + second header staged in envelope | **DUPLICATE_SNAPSHOT_FAILURE** |
| Same meeting + legacy path without event-linked header | Permitted coexistence until E-02 population — new rows are INSERT-only for current event |

## 9. One-to-one event binding

E-01 defines: **one Resolution Snapshot per Freeze Event** (INV-7).

| Rule | Requirement |
|------|-------------|
| Cardinality | `freeze_event_id` → exactly one `owner_vote_resolution_snapshot` row |
| Duplicate prohibition | Second header for same Freeze Event **shall fail closed** |
| Committed-primary case | Handled by Phase 1 **IDEMPOTENT RETURN** before IU-2.2 executes |
| Database enforcement | Unique index `owner_vote_resolution_snapshot_one_per_freeze_event` |

In-envelope duplicate detection **shall** precede or accompany persistence staging — do not rely solely on constraint catch for correctness signaling.

---

## 10. Freeze-time consistency

IU-2.2 **shall** use the **same logical freeze boundary** as IU-2.1.

| Rule | Requirement |
|------|-------------|
| `frozen_at` source | Same authoritative `freezeBoundaryAt` established in the atomic envelope |
| Prohibition | No new freeze instant · no later independent timestamp · no per-row regeneration |
| Effect | Voter Snapshot and Resolution Snapshot represent **one logical Freeze Event** |

`ResolutionSnapshot.frozen_at` **SHALL equal** `freezeBoundaryAt` used for all IU-2.1 voter rows.

## 11. Source → target mapping

Deterministic mapping contract:

| Source | Target | Transformation | Nullable | Validation | Failure |
|--------|--------|----------------|----------|------------|---------|
| `FreezeContext.freezeEventId` | `freeze_event_id` | Direct | NO | UUID present | `CORRELATION_FAILURE` |
| `FreezeContext.meetingId` | `owner_vote_meeting_id` | Direct | NO | UUID match meeting | `CORRELATION_FAILURE` |
| `FreezeContext.propertyId` | `property_id` | Direct | NO | UUID match property + meeting binding | `CORRELATION_FAILURE` |
| Envelope `freezeBoundaryAt` | `frozen_at` | Direct uniform value | NO | Same as IU-2.1 | `TRANSACTION_FAILURE` |
| Insert instant | `created_at` | Orchestration timestamp | NO | Per row | `PERSISTENCE_FAILURE` |
| Orchestration | `id` | New UUID v4 | NO | Unique within attempt | `DUPLICATE_SNAPSHOT_FAILURE` |

**No header-level mapping** from live resolution content fields (`title`, `description`, `threshold`, etc.) — those map in IU-2.3 to `owner_vote_frozen_motions`.

## 12. Instrument semantics

The Resolution Snapshot header represents the **frozen resolution instrument container** — not the complete instrument content.

| Rule | Requirement |
|------|-------------|
| Header scope | Correlation + parent identity only |
| Motion content | **IU-2.3** — `owner_vote_frozen_motions` |
| Header substitution | Header **shall not** substitute for complete motion set |
| Complete instrument domain | Resolution Snapshot **+** Frozen Motions |

Therefore:

```
IU-2.2 success alone ≠ complete Phase 2 instrument materialization
IU-2.2 success alone ≠ MI-3 Complete Materialization
```

IU-2.2 **shall not** duplicate Frozen Motion content into the header unless explicitly required by E-01 schema (it is not).

Every materialized Resolution Snapshot **shall** satisfy:

| Required equality |
|-------------------|
| `snapshot.freeze_event_id = FreezeContext.freezeEventId` |
| `snapshot.owner_vote_meeting_id = FreezeContext.meetingId` |
| `snapshot.property_id = FreezeContext.propertyId` |

Shared with IU-2.1:

| Shared element |
|----------------|
| Same `FreezeContext` |
| Same attempt identity |
| Same atomic envelope |
| Same `freezeBoundaryAt` |

**Prohibited:** Cross-event · cross-meeting · cross-property correlation

Correlation mismatch **shall** fail materialization → `CORRELATION_FAILURE`

On success, IU-2.2 **shall** expose via `FreezeContext` subordinate metadata:

| Hand-off element |
|------------------|
| `resolutionSnapshotId` |
| `freezeEventId` |
| `meetingId` |
| `propertyId` |
| `freezeBoundaryAt` |
| Same `FreezeContext` |

| Same atomic envelope |

IU-2.3 **shall** bind every Frozen Motion to this exact `resolutionSnapshotId`. IU-2.3 **shall not** create an alternate parent.

## 15. Immutability interaction

E-01 event-linked immutability applies when `freeze_event_id IS NOT NULL` (trigger `trg_owner_vote_resolution_snapshot_event_linked_immutable` per E-01 IU-3.2).

| Rule | Requirement |
|------|-------------|
| IU-2.2 rows | **Always** event-linked — `freeze_event_id` set |
| Post-materialization mutation | **Prohibited** — no UPDATE/DELETE after staging within committed envelope |
| Post-commit correction | **E-06** only |

IU-2.2 **shall not** depend on UPDATE after materialization, DELETE + rebuild after commit, post-commit mutation, or silent replacement.

## 16. Materialization algorithm

```
Receive authoritative FreezeContext (post IU-2.1 MATERIALIZED)
        ↓
Verify entry contract (§4)
        ↓
Verify materialization-active envelope
        ↓
Load meeting binding authority (owner_vote_meetings)
        ↓
Validate meeting / property binding
        ↓
Load instrument completeness authority (owner_vote_resolutions)
        ↓
Validate source completeness (≥ 1 valid resolution row)
        ↓
Generate stable Resolution Snapshot id
        ↓
Map source → header contract (§11)
        ↓
Validate freeze / event correlation (§13)
        ↓
Stage one Resolution Snapshot inside existing envelope
        ↓
Verify one-to-one Freeze Event binding (§9)
        ↓
Expose resolutionSnapshotId on FreezeContext
        ↓
Return RESOLUTION_MATERIALIZED
```

**No independent commit.**

## 17. Result contract

IU-2.2 **shall** return **one deterministic result**.

| Outcome | Meaning |
|---------|---------|
| **RESOLUTION_MATERIALIZED** | IU-2.2 materialization success |
| **INVALID_SOURCE** | Source row fails validity (e.g. empty title on all rows) |
| **MISSING_RESOLUTION_SOURCE** | No qualifying `owner_vote_resolutions` rows for meeting |
| **CORRELATION_FAILURE** | Meeting/property/freeze correlation mismatch |
| **DUPLICATE_SNAPSHOT_FAILURE** | More than one header for same Freeze Event |
| **PERSISTENCE_FAILURE** | Staging or persistence failure |
| **TRANSACTION_FAILURE** | Transaction envelope or ownership failure |

Only **RESOLUTION_MATERIALIZED** means IU-2.2 success.

No IU-2.2 result means **COMMITTED** or **COMMIT_READY**. No partial-success outcome exists.

## 19. Duplicate contract

### 19.1 Invalid duplicate

| Condition | Classification |
|-----------|----------------|
| More than one Resolution Snapshot for same `freeze_event_id` | **Invalid duplicate** — fail closed |

### 19.2 Valid multiplicity (not header duplication)

| Condition | Classification |
|-----------|----------------|
| N `owner_vote_resolutions` rows for same meeting | **Valid** — one header; N motions in IU-2.3 |
| Same live resolution referenced by multiple frozen motions | **IU-2.3 concern** — not header multiplication |

IU-2.2 **shall not** collapse multiple formal motions into multiple Resolution Snapshot headers. **Exactly one header. N motions later.**

## 20. Source version / frozen evidence

E-01 header schema provides **no** source-version columns. Therefore:

| Evidence type | Header level | Motion level (IU-2.3) |
|---------------|--------------|------------------------|
| Live resolution ID | **Not stored** | `source_resolution_id` |
| Agenda item ID | **Not stored** | `source_agenda_item_id` |

IU-2.2 **shall not** invent new target columns. Source-version evidence **shall** be preserved through IU-2.3 source bindings where authorized by E-01.

## 22. Rollback interaction

IU-2.2 does **NOT** own an independent rollback transaction.

Failure propagates to the Phase 1 transaction owner. The Phase 1 Rollback Contract governs cleanup of:

```
IU-2.1 staged voters
+ IU-2.2 staged Resolution Snapshot
+ future IU-2.3 staged motions
```

If IU-2.2 fails, **no durable partial Phase 2 materialization** may survive.

---

## 23. Idempotency interaction

| **RETRYABLE** | IU-2.2 does not execute |

IU-2.2 **shall not:** independently rebuild a committed Resolution Snapshot · decide transaction ownership · bypass Phase 1 validation.
