## 1. Purpose

Define the **executable implementation design baseline** for **RU-1.2 — Server-Side Atomic Commit Envelope, Ownership & Reconciliation**.

RU-1.2 establishes how a future authorized server-side holder executes **one PostgreSQL transaction** that:

1. reconciles durable state
2. acquires meeting-scoped execution exclusion
3. validates ownership and prerequisites
4. materializes / verifies Artifacts **A–G**
5. **INSERT** Primary Audit **G** in the same transaction
6. returns a certified outcome taxonomy (**IDEMPOTENT_RETURN** · **RETRYABLE** · **NEW_ATTEMPT_REQUIRED**)

RU-1.2 **does not** certify Runtime **COMMITTED**, final property_id closure (RU-1.3), consumer wiring, or Project Certification.

## 6. Transaction envelope contract

Logical envelope inside proposed RPC (single implicit transaction):

| Step | Action |
|------|--------|
| 1 | Authenticate · authorize caller · resolve `owner_vote_meeting_id` / tenant |
| 2 | **Durable reconciliation** (read-only queries) |
| 3 | If committed primary A–G exists → **IDEMPOTENT_RETURN** (early exit) |
| 4 | Acquire meeting-scoped transaction exclusion (`pg_try_advisory_xact_lock`) |
| 5 | If lock unavailable → **RETRYABLE** (early exit) |
| 6 | Validate Phase 1/2/3 prerequisites · attempt identity |
| 7 | Stage / verify **A** Freeze Event (primary INSERT) |
| 8 | Materialize / verify **B** Voter snapshots |
| 9 | Materialize / verify **C** Resolution snapshot header |
| 10 | Materialize / verify **D** Frozen motions |
| 11 | Verify **F** meeting lifecycle compatibility — **no status UPDATE** |
| 12 | Stage **E** marker — `snapshot_frozen_at` UPDATE |
| 13 | Construct **G** evidence · cross-column validation |
| 14 | **INSERT** `owner_vote_primary_freeze_audits` |
| 15 | Final pre-return verification (**ATOMIC_SET_COMPLETE**) |
| 16 | Return success payload (pre-commit envelope complete — **≠ COMMITTED**) |

**Exception at any step 7–15:** entire transaction **ROLLBACK** — no partial durable A–G.

```
Postgres function does NOT issue COMMIT.
COMMIT occurs only after successful function return.
```

## 9. Ownership model — ERQ-1.2-003 / ERQ-1.2-004 / ERQ-1.2-005

### 9.1 Certified semantics (consumed)

| Rule | Source |
|------|--------|
| One active owner per meeting freeze attempt | Phase 1 · IU-3.3 |
| Competitor → **RETRYABLE** | IU-3.3 Completion §8 |
| Committed durable result → **IDEMPOTENT_RETURN** | IU-3.3 |
| Rollback / no owner → **NEW_ATTEMPT_REQUIRED** | IU-3.3 |
| Identities never reused after rollback | Phase 3 · IU-3.3 |
| No ownership stealing | Phase 1 · IU-3.3 |

### 9.2 Options evaluated

| Option | In-flight exclusion | Durable reconciliation signal | Stale row risk | Disposition |
|--------|--------------------|------------------------------|----------------|-------------|
| **A. Transaction advisory lock only** | ✓ | Committed A–G rows only | None | **PROPOSED component** |
| **B. Durable ownership table** | ✓ if maintained | Row state | Stale "active" without reconciliation | **PROPOSED optional — not required if DR confirms** |
| **C. Freeze event as owner** | ✗ pre-commit | Post-commit only | — | **Insufficient alone** |
| **D. Meeting `FOR UPDATE`** | ✓ | None durable for in-flight | Lock duration = txn | **Alternative — Design Review** |
| **E. Hybrid: xact lock + durable artifact reconciliation** | ✓ | Committed artifacts | Low | **PROPOSED — PREFERRED** |

### 9.3 Proposed ownership model

**Hybrid architecture (proposed):**

| Concern | Mechanism |
|---------|-----------|
| **In-flight exclusion** | Meeting-scoped `pg_try_advisory_xact_lock(lock_key)` at transaction start |
| **Lock key** | Deterministic 64-bit key from `hashtext('e02_owner_vote_freeze:' || owner_vote_meeting_id::text)` *(Design Review exact formula)* |
| **Active owner semantics** | Holder of advisory xact lock **within live PostgreSQL transaction** |
| **Lock release** | Automatic on COMMIT or ROLLBACK |
| **Durable ownership evidence** | **Committed** A–G artifact rows — not lock state |
| **Post-rollback** | No lock · no committed primary → **NEW_ATTEMPT_REQUIRED** |
| **Post-commit uncertain ack** | Reconciliation reads committed A–G → **IDEMPOTENT_RETURN** |

### 9.4 Durable ownership table — explicit answer (ERQ-1.2-005)

| Question | Proposed answer |
|----------|-----------------|
| Does IU-3.3 **require** a separate durable ownership persistence table? | **NOT REQUIRED** if reconciliation reads authoritative committed artifacts and in-flight exclusion uses transaction-scoped lock |
| Can ownership be freeze event + audit rows + lock? | **Partially** — committed state yes; in-flight state requires **transaction lock**, not durable row |
| When is durable table needed? | Only if Design Review finds partial durable artifact rows possible on failure **or** reconciliation cannot distinguish committed vs in-flight without extra state |

**Truth table — process outcomes:**

| Scenario | Lock | Committed A–G | Durable owner row needed? | Outcome |
|----------|------|---------------|---------------------------|---------|
| Happy path commit | Released at commit | **Yes** | No | Success payload · future RU-1.3 **COMMITTED** |
| Exception mid-txn | Released at rollback | **No** | No | **NEW_ATTEMPT_REQUIRED** (new IDs) |
| Competitor while A running | B lock fails | **No** | No | **RETRYABLE** |
| A committed · B arrives | — | **Yes** | No | **IDEMPOTENT_RETURN** |
| A commit · ack lost | — | **Yes** | No | Reconcile → **IDEMPOTENT_RETURN** |
| Connection drop mid-txn | Rollback releases | **No** | No | Reconcile → **NEW_ATTEMPT_REQUIRED** |

```
ERQ-1.2-003  PROPOSED — hybrid lock + durable artifact reconciliation
ERQ-1.2-004  PROPOSED — advisory xact lock sufficient for in-flight exclusion (Design Review)
ERQ-1.2-005  PROPOSED — separate ownership table NOT REQUIRED (Design Review)
```

## 10. Ownership lifetime

| Phase | Ownership representation |
|-------|-------------------------|
| **Acquisition** | Successful `pg_try_advisory_xact_lock` after reconciliation passes |
| **Validation / materialization** | Lock held · single transaction |
| **Audit preparation / G INSERT** | Same transaction |
| **Successful return** | Lock released · committed artifacts become durable evidence |
| **Rollback** | Lock released · **no durable owner** · identities terminal |
| **Timeout / lost ack (after commit)** | Lock already released · reconciliation uses **committed artifacts only** |

**Prohibited:** durable `"active"` flag without reconciliation semantics or TTL/heartbeat (not certified).

## 19. Lock granularity · advisory vs row lock

| Mechanism | Proves | Does not prove |
|-----------|--------|----------------|

**Proposed:** advisory **xact** lock (releases on commit/rollback) — not session lock.
