## 1. Purpose

Define the **engineering implementation design** for **IU-3.2 — Primary Audit**.

IU-3.2 **shall** consume the certified IU-3.1 **COMMIT_PREPARED** hand-off, construct/stage exactly **one** authoritative Primary Freeze Audit (Artifact **G**), verify the full Atomic Commit Set **A – G**, and produce local terminal state **AUDIT_PREPARED** for IU-3.3 / final commit orchestration.

IU-3.2 **shall not:** perform final database **COMMIT** · produce **COMMITTED** · implement IU-3.3 idempotent retry · repair IU-3.1 · re-materialize Phase 2 · update `owner_vote_meetings.status` · invoke legacy freeze RPC.

This document resolves Phase 3 Plan **CQ-003** at design-contract level and **shall not redefine** Architecture Authority or the IU-3.1 Completion baseline.

```
COMMIT_PREPARED
        ↓

        ↓

        ↓

        ↓

AUDIT_PREPARED
        ↓

        ↓
COMMITTED (only after successful DB COMMIT)
```

**IU-3.2 local terminal success:** **`AUDIT_PREPARED`**

**IU-3.2 NEVER produces `COMMITTED`.**

## 6. Artifact G — Primary Freeze Audit contract

### 6.1 Cardinality (INV-5 / CI-4)

```
1 committed primary Freeze Event → exactly 1 Primary Freeze Audit
```

| Prohibited |
|------------|
| Zero audit on successful **COMMITTED** |
| Multiple primary audits for same `freezeEventId` |
| One audit covering unrelated freeze events |
| Audit identity based **only** on `meetingId` |
| Duplicate audit on retry of same committed event |

**Authoritative uniqueness dimension (logical):** `freeze_event_id` — **not** meeting alone.

### 6.2 Minimum evidence (logical contract)

Primary Audit **shall** prove:

| # | Evidence element |
|---|------------------|
| 1 | `freezeEventId` |
| 2 | `meetingId` |
| 3 | `propertyId` |
| 4 | Transaction attempt identity |
| 5 | `freezeBoundaryAt` |
| 6 | Primary Freeze Event identity (`is_primary` correlation) |
| 7 | Materialization completeness summary |
| 8 | Voter snapshot completion |
| 9 | Resolution snapshot completion |
| 10 | Frozen motion completion |
| 11 | Commit-set verification result |
| 12 | Marker relationship (`snapshot_frozen_at` / `frozen_at` staging state) |
| 13 | Transaction outcome (pre-commit: **staged success** — not **COMMITTED**) |
| 14 | Commit timestamp / durable commit evidence (see §11) |
| 15 | Audit type/version identifier (logical — e.g. `primary_freeze_audit_v1`) |
| 16 | Correlation to same atomic envelope where representable |

### 6.3 Distinctions (mandatory)

| Type | Role |
|------|------|
| **Primary Freeze Audit** | Artifact **G** — atomic commit set member |
| Diagnostic / retry telemetry | IU-3.3 / orchestration — **not** Artifact G |
| Legacy `owner_vote_audit_logs.snapshot_frozen` | Production legacy — **not** E-02 authoritative without redesign |
| `meeting_formal_resolution_audit` | Authoring domain — **not** Artifact G |

**Default principle:**

```
Abandoned / rolled-back attempt identity must not become

```

Artifact **G** **must** share with **A – F**:

| Dimension |
|-----------|
| Same database transaction |
| Same Phase 1 atomic envelope |
| Same `freezeEventId` |
| Same `meetingId` |
| Same `propertyId` |
| Same attempt |
| Same `freezeBoundaryAt` |

**Prohibited:**

| Prohibition |
|-------------|
| Independent transaction for audit |
| Post–DB-COMMIT audit backfill |
| Commit snapshots before audit staging |
| Audit failure still allowing **COMMITTED** |
| Telemetry success substituting for Primary Audit |

**Core rule:**

```
NO PRIMARY AUDIT → NO COMMITTED FREEZE
```

(Staged audit within open transaction satisfies IU-3.2; durable **COMMITTED** requires successful DB COMMIT including G — IU-3.3/final orchestration scope.)

## 11. Commit timestamp contract

Three concepts **shall not** be conflated:

| Concept | Role |
|---------|------|
| **`freezeBoundaryAt`** | Logical governance freeze boundary — envelope authority from Phase 1/2/IU-3.1 |
| **`commitTimestamp`** | Durable commit instant evidence — **authoritative semantics TBD at persistence** |
| **`audit created_at`** | Row insert metadata — **alone insufficient** as full commit authority |

### Design answers (AQ-006 / AQ-007)

| Question | Design-contract answer |
|----------|------------------------|
| When is `commitTimestamp` produced? | Captured at **final DB COMMIT** boundary — orchestration assigns authoritative value **at or immediately before** COMMIT success confirmation |
| Pre- or post-COMMIT in audit row? | Audit row **staged pre-COMMIT** in same transaction; `commitTimestamp` field may be populated with envelope-assigned value aligned to COMMIT instant — **exact persistence TBD** |
| Same-transaction representation | Staged audit row includes logical commit evidence slot; durable meaning confirmed only after COMMIT |
| DB transaction timestamp only? | Acceptable **if** explicitly documented as authoritative commit evidence at EIR — not assumed PASS now |
| Is `created_at` sufficient? | **No** as sole commit authority — may supplement but **not** replace `freezeBoundaryAt` / explicit commit evidence distinction |
| Schema support needed? | **Yes** — dedicated `committed_at` or structured evidence field **recommended** in NEW TARGET — **schema obligation** |

No invented column claimed as existing in migration head.

## 13. Local state model

```
COMMIT_PREPARED
        ↓
AUDIT_TARGET_VERIFIED
        ↓
AUDIT_EVIDENCE_ASSEMBLED
        ↓
AUDIT_STAGED
        ↓
ATOMIC_SET_COMPLETE
        ↓
AUDIT_PREPARED
```

**Failure branch:**

```
any pre-COMMIT failure → FAIL CLOSED → ROLLING_BACK → ROLLED_BACK
```

**`COMMITTED` shall not appear as IU-3.2 local output.**

Intermediate states support deterministic orchestration and EIR injection points; semantic order is fixed even if physical SQL order varies (ACQ-005 preservation).

## 15. Rollback contract

Any failure before durable **COMMITTED**:

```
FAIL CLOSED → Phase 1 transaction owner → ROLLING_BACK → full envelope rollback → ROLLED_BACK
```

**Rollback includes:**

| Domain |
|--------|
| Phase 2 voter / resolution / motion rows |
| Freeze Event staging |
| Freeze marker staging |
| Primary Audit staging |
| IU-3.1 commit-preparation state |

**Prohibited survivors:**

| Invalid state |
|---------------|
| Orphan audit |
| Audit without snapshots |
| Snapshots without audit (at commit eligibility) |
| Marker without audit |
| False primary audit |
| False **COMMITTED** evidence |

No meeting `status` rollback (Artifact F verify-only — IU-3.1 locked).

## 16. Idempotency / IU-3.3 boundary

IU-3.2 **defines interaction only** — IU-3.3 **owns** closure.

| Scenario | Expected behavior (preserved for IU-3.3) |
|----------|------------------------------------------|

| Active competitor | **RETRYABLE** — no second audit |

IU-3.2 **shall not** silently reuse abandoned audit identity.
