## 1. Purpose

Define the **engineering implementation design** for **IU-3.1 — Atomic Commit**.

IU-3.1 **shall consume** the certified Phase 2 **COMMIT_READY** hand-off and establish the authoritative **commit-preparation contract**.

IU-3.1 **shall:**

| # | Responsibility |
|---|----------------|
| 1 | Final Commit Preconditions |
| 2 | Atomic Commit Set Verification |
| 3 | Freeze Marker staging |
| 4 | Meeting freeze-state / phase transition staging |
| 5 | Freeze Event primary finalization staging |
| 6 | **COMMIT_PREPARED** state for downstream IU-3.2 / IU-3.3 |

IU-3.1 **shall not:**

| Exclusion | Owner |
|-----------|-------|
| Primary Freeze Audit final persistence contract | **IU-3.2** |
| Idempotent Retry / concurrency closure | **IU-3.3** |
| Final **COMMITTED** transition before required downstream commit artifacts exist | Phase 3 overall sequence |
| Voting · scheduler · E-03 | Other epics |

**Normative boundary:**

```
IU-3.1 DOES NOT by itself certify or produce final COMMITTED.
```

This document implements [`E-02-Phase-3-Implementation-Plan.md`](E-02-Phase-3-Implementation-Plan.md) §IU-3.1 and **shall not redefine** architecture decisions in [`E-02-Architecture.md`](E-02-Architecture.md).

## 3. Objective

**Transform the certified Phase 2 COMMIT_READY state into a fully verified and staged Atomic Commit Set, ready for Primary Audit and final commit closure.**

**IU-3.1 local terminal state:**

```
COMMIT_PREPARED
```

**Normative state separation:**

```
COMMIT_READY ≠ COMMIT_PREPARED ≠ COMMITTED
```

**COMMIT_PREPARED** means:

| Property | State |
|----------|-------|
| Commit preconditions | **PASS** |
| Authoritative commit set | **Verified** (artifacts A–F) |
| Freeze marker | **Staged** (not independently durable) |
| Meeting transition | **Staged** (not independently durable) |
| Freeze Event primary finalization | **Staged** (not independently durable) |
| Transaction envelope | **Open** — same Phase 1 envelope |
| Primary audit / final DB COMMIT | **Not yet complete** |

## 6. Atomic commit set

IU-3.1 **shall verify** the full Atomic Commit Set defined in Phase 3 Plan §9.

| Set | Artifact | IU-3.1 responsibility |
|-----|----------|----------------------|
| **A** | Freeze Event | Verify + stage primary finalization |
| **B** | Voter Snapshot | Verify completeness + correlation |
| **C** | Resolution Snapshot | Verify exactly one header |
| **D** | Frozen Motions | Verify complete motion set |
| **E** | Freeze Marker | Stage `snapshot_frozen_at` (+ aligned `frozen_at`) |
| **F** | Meeting state / phase transition | Stage `status` transition |
| **G** | Primary Freeze Audit | **Required final artifact — IU-3.2 owns materialization** |

**Dependency rule:**

```
IU-3.1 cannot declare the full atomic commit set complete until IU-3.2 supplies G.
```

IU-3.1 owns preparation and verification for **A–F**. Artifact **G** remains a mandatory downstream dependency, not an IU-3.1 local completion claim.

## 8. Freeze Event finalization contract

### Repository schema (verified)

Table: `public.owner_vote_freeze_events` (migration `20261725120000`)

| Column | Type | IU-3.1 use |
|--------|------|------------|
| `id` | uuid PK | Same as `FreezeContext.freezeEventId` |
| `owner_vote_meeting_id` | uuid NOT NULL | Must equal `meetingId` |
| `property_id` | uuid NOT NULL | Must equal `propertyId` |
| `frozen_at` | timestamptz NOT NULL | Stage aligned with `freezeBoundaryAt` — **ACQ-004** |
| `is_primary` | boolean NOT NULL DEFAULT true | Stage `true` for authoritative primary |
| `created_at` | timestamptz NOT NULL | Row creation — not commit timestamp authority |

**No separate status/commit-state column exists in repository.**

### Staging contract

IU-3.1 **shall stage** authoritative primary finalization:

| Target | Rule |
|--------|------|
| Identity | Same `freezeEventId` |
| Correlation | Same `meetingId` · same `propertyId` |
| `frozen_at` | Aligned with `freezeBoundaryAt` — not ad hoc `now()` |
| `is_primary` | `true` for this authoritative attempt |
| Uniqueness | Preserved under partial unique index |

**Normative rule:**

```
Staging is_primary = true alone SHALL NOT mean COMMITTED.
```

Only successful final database **COMMIT** (after IU-3.2 satisfies artifact G) may be interpreted as durable committed primary.

## 9. Primary uniqueness contract

### Repository constraint (verified)

```sql
CREATE UNIQUE INDEX owner_vote_freeze_events_one_primary_per_meeting
  ON public.owner_vote_freeze_events (owner_vote_meeting_id)
  WHERE is_primary IS TRUE;
```

**Verified scope:** **One `is_primary = true` row per `owner_vote_meeting_id`** — i.e., per meeting, not per distinct freeze boundary timestamp.

Migration comment notes E-06 reissue may set prior rows `is_primary = false` before inserting a new primary.

### Plan contract

| Rule | Requirement |
|------|-------------|
| Committed primary | At most one per meeting under index semantics |
| Conflicting primary | Prevents commit preparation — **PRIMARY_CONFLICT** |
| Second primary staged | Must not succeed while index conflict exists |

**Design Question ACQ-001:** Whether deployed index scope matches Architecture "meeting freeze boundary" semantics or only "per meeting" — **Design Review must confirm**. Do not expand constraint semantics beyond repository evidence.

## 15. Marker / transition staging order

### Proposed deterministic order

```
1. Verify COMMIT_READY
2. Verify commit set (CP-1 … CP-14 + correlation)
3. Verify primary uniqueness (no conflicting primary)
4. Verify marker target (snapshot_frozen_at not conflicting)
5. Verify meeting transition (source → target valid)
6. Stage Freeze Event primary finalization (frozen_at, is_primary)
7. Stage meeting freeze marker (snapshot_frozen_at = freezeBoundaryAt)
8. Stage meeting state/phase transition (status)
9. Verify artifacts A–F complete and correlated
10. Return COMMIT_PREPARED
```

**Flexibility:** Design Review **may adjust steps 6–8** if actual FK / trigger / constraint dependencies require different ordering. Order **shall not** contradict repository schema behavior.

**Design Question ACQ-005:** Required staging order given actual FK / trigger / constraint dependencies — **Design Review verifies**.

**Design Question ACQ-010:** Whether any existing trigger writes marker/status outside intended atomic sequence — **repository verify at Design Review**.

```
        ↓

        ↓

        ↓

        ↓
```


**COMMITTED shall not appear as IU-3.1 local output.**

## 19. Rollback interaction

IU-3.1 **does not own** an independent rollback transaction. It **continues** the Phase 1 Rollback Contract.

| Resolution Snapshot |
| Frozen Motions |
| Staged Freeze Event primary changes |
| Staged marker |
| Staged meeting transition |
| Future IU-3.2 staged audit |

**No partial durable freeze** may survive.

## 23. COMMITTED boundary

**Normative section — IU-3.1 SHALL NOT produce COMMITTED.**

The following **do not** equal **COMMITTED:**

| State / event |
|---------------|
| **COMMIT_SET_VERIFIED** |
| `is_primary` staged |
| `snapshot_frozen_at` staged |
| Meeting `status` staged |
| **COMMIT_PREPARED** |

**COMMITTED** requires:

| Requirement |
|-------------|
| IU-3.2 Primary Audit satisfied (artifact G) |
| Required Phase 3 commit set complete (A–G) |
| Final DB transaction **COMMIT** succeeds |

Final **COMMITTED** closure belongs to Phase 3 overall / downstream IU sequence — **not** IU-3.1 local success.
