## 13. C9 — Successful durable DB COMMIT (central resolution)

### 13.1 Certified requirement

Phase 3 §13 #9 · IU-3.3 II-8: **Successful durable DB COMMIT** mandatory for **COMMITTED**.

### 13.2 Design Review principle — **RA-RU-1.3-001**

**Approved C9 proof rule (Durable Visibility Rule):**

> **C9 is satisfied if and only if** components **C1–C8** are all satisfied when observed from an **authoritative durable read in a subsequent independent database read context** (i.e., not merely from the RU-1.2 write transaction's pre-return in-function view).

**PostgreSQL rationale:** Under normal READ COMMITTED / Supabase default isolation, if a **later independent transaction** can read the **complete correlated A–G row set**, those rows were **durably committed** by the earlier RU-1.2 transaction. Uncommitted writes from rolled-back transactions are not visible.

### 13.3 Explicit exclusions from C9 proof

| Signal | C9 proof? |
|--------|-----------|
| RPC returned `ATOMIC_ENVELOPE_COMPLETE` | **NO** |
| Client received response | **NO** |
| `transaction_reference_at` alone | **NO** |
| `created_at` alone | **NO** |
| Pre-commit in-function helper FULL | **NO** |
| Staged rows visible only inside open write txn | **NO** |

### 13.4 Lost-ack proof (locked)

1. Client invokes RU-1.2.
2. RU-1.2 transaction **commits**.
3. Response **lost**.
4. Later **independent** authority evaluation reads durable C1–C8.
5. Complete correlated rows **visible** → **C9 satisfied**.
6. Classification = **COMMITTED**.
7. Subsequent write-path reconciliation = **IDEMPOTENT_RETURN**.

### 13.5 Rollback proof

RU-1.2 rollback → no new complete A–G durable footprint → C9 **not satisfied** → **NOT_COMMITTED** / no fabricated audit/marker.

### 13.6 Partial corruption proof

Some but not all C1–C8 visible with inconsistent correlation → **FAIL_CLOSED** (not rollback-assumed clean NOT_COMMITTED).

## 14. Durable visibility rule (formal)

**RA-RU-1.3-001 — LOCKED**

```
C9 := (C1–C8 evaluated from post-transaction durable read)
      AND (evaluator session is independent of the original write transaction)
      AND (complete correlated set visible)
```

Authority evaluator **must not** accept its own write-transaction pre-return evaluation as C9 proof.

---

## 15. Same-transaction evaluation prohibition

**LOCKED:**

```
PRE-COMMIT FULL (inside RU-1.2 before COMMIT) ≠ COMMITTED
ATOMIC_ENVELOPE_COMPLETE (RPC return label) ≠ COMMITTED
```

RU-1.2 `_ru12_evaluate_durable_state` during steps 2/4 may read **previously committed** state from **earlier transactions** — that read **can** support C9 for **IDEMPOTENT_RETURN** cases where full envelope pre-existed.

Fresh-write success path: rows become C9-eligible **only after** the write transaction commits and a **subsequent read** evaluates them.

## 17. IDEMPOTENT_RETURN relationship

| Situation | Context | C9 implication |
|-----------|---------|----------------|
| Pre-lock initial reconciliation | New txn reading **previously committed** state | If C1–C8 complete → **C9 can be satisfied** via visibility rule |
| Post-lock double-check | Same RPC txn · reads **earlier committed** state | Same — prior commit visible |
| Fresh write success | Returns `ATOMIC_ENVELOPE_COMPLETE` | C9 **not proven until post-commit read** |

**ERQ-1.3-002 resolution:**

> **C — RU-1.2 `IDEMPOTENT_RETURN` is an orchestration hint only.** Authority evaluator **must independently re-run** full **C1–C9** in post-transaction read context. When predicate satisfied → **COMMITTED**. Terminology equivalence **not assumed**.
