## 4. Production source authority baseline

The authoritative live Resolution source consists of **two cooperating production layers**.

### 4.1 Meeting binding

| Field | Definition |
|-------|------------|
| **Source relation** | `public.owner_vote_meetings` |
| **Selection** | `id = FreezeContext.meetingId` |
| **Property binding** | `property_id = FreezeContext.propertyId` |

The meeting establishes the authoritative meeting/property boundary for the frozen instrument set.

### 4.2 Instrument set

| Field | Definition |
|-------|------------|
| **Source relation** | `public.owner_vote_resolutions` |
| **Meeting filter** | `meeting_id = FreezeContext.meetingId` |
| **Row validity** | Non-empty `title` after trim |

### 4.3 Explicit exclusions

The following are **not** authoritative IU-2.2 header sources:

| Excluded source |
|-----------------|
| `community_resolutions` |
| Agenda-only authoring state |
| Voter snapshot rows |
| Ballots |
| Legacy voter freeze output |

These sources **must not** substitute for `owner_vote_meetings` + `owner_vote_resolutions`.

## 5. Instrument cardinality baseline

The authoritative cardinality model is:

```
N live owner_vote_resolutions
        ↓
1 owner_vote_resolution_snapshot header
        ↓
N owner_vote_frozen_motions
```

The Resolution Snapshot header represents the frozen **instrument container**, not an individual live Resolution row.

| Rule | Requirement |
|------|-------------|
| One live Resolution | Does **not** create one header |
| Multiple live Resolutions | Do **not** create multiple headers |
| One Freeze Event | Exactly **one** header |
| Individual Resolution content | Materialized as Frozen Motions in IU-2.3 |

This **N → 1 → N** model is authoritative for downstream E-02 work.

---

## 6. Resolution Snapshot target baseline

IU-2.2 targets the E-01-certified table: **`public.owner_vote_resolution_snapshot`**

| Column | Role |
|--------|------|
| `id` | Stable header identity |
| `freeze_event_id` | Freeze Event correlation |
| `owner_vote_meeting_id` | Meeting correlation |
| `property_id` | Property correlation |
| `frozen_at` | Logical freeze instant |
| `created_at` | Persistence metadata |

The header contains **no** individual motion content. Motion-level title, text, provenance, agenda linkage, or formal-resolution version evidence belongs to **IU-2.3**.

---

## 7. Resolution Snapshot identity baseline

Each new Resolution Snapshot header receives a newly generated UUID: **`resolutionSnapshotId`**.

| Rule | Requirement |
|------|-------------|
| Not copied from live source | **Not** `owner_vote_resolutions.id` |
| Uniqueness | Unique to the frozen Resolution Snapshot |
| Freeze Event binding | Bound to authoritative Freeze Event |
| Stability | Remains stable throughout frozen instrument lifecycle |
| Parent role | Mandatory parent for all IU-2.3 Frozen Motions |

The generated `resolutionSnapshotId` is added to `FreezeContext` **only after** successful IU-2.2 materialization.

---

## 8. One-to-one Freeze Event binding

The authoritative relationship is:

**1 Freeze Event ↔ 1 Resolution Snapshot Header**

More than one Resolution Snapshot header for the same `freeze_event_id` is **invalid**.

| Enforcement | Detail |
|-------------|--------|
| Persistence | Unique index `owner_vote_resolution_snapshot_one_per_freeze_event` |
| Committed primary | Phase 1 **IDEMPOTENT RETURN** before IU-2.2 executes |
| Prohibition | IU-2.2 does not rebuild or replace committed Resolution Snapshot |

---

## 9. Freeze-time baseline

IU-2.2 **must** use the same logical freeze instant established for the entire Freeze Event:

```
owner_vote_resolution_snapshot.frozen_at = FreezeContext.freezeBoundaryAt
```

IU-2.2 **must not** generate an independent freeze timestamp.

The following **must** share the same logical freeze boundary:

| Artifact |
|----------|
| Freeze Event |
| IU-2.1 Voter Snapshot |
| IU-2.2 Resolution Snapshot |
| IU-2.3 Frozen Motions |

`created_at` remains persistence metadata and does **not** redefine the logical freeze instant.

## 10. Source completeness baseline

IU-2.2 may succeed **only** when:

| Requirement |
|-------------|
| Authoritative meeting exists |
| Meeting belongs to expected property |
| ≥1 qualifying `owner_vote_resolutions` row belongs to meeting |
| Each qualifying row satisfies required source validity |
| Instrument set is unambiguous |

| Condition | Outcome |
|-----------|---------|
| Zero qualifying Resolution rows | **MISSING_RESOLUTION_SOURCE** |
| Empty-title rows | Excluded from qualifying set |
| Exclusion leaves zero qualifying rows | **MISSING_RESOLUTION_SOURCE** |
| Ambiguous or invalid source | **Fail closed** |

## 11. Source-to-target mapping baseline

Resolution Snapshot header mapping is **deterministic**.

| Target | Authoritative source |
|--------|----------------------|
| `id` | Newly generated `resolutionSnapshotId` |
| `freeze_event_id` | `FreezeContext.freezeEventId` |
| `owner_vote_meeting_id` | `FreezeContext.meetingId` |
| `property_id` | `FreezeContext.propertyId` |
| `frozen_at` | `FreezeContext.freezeBoundaryAt` |
| `created_at` | Persistence metadata |

No individual live Resolution identity is copied into the header. No motion provenance belongs in the header.

## 13. Correlation baseline

Every IU-2.2 artifact **must** correlate to the same authoritative Freeze Context used by IU-2.1.

| Required equality |
|-------------------|
| `freeze_event_id = FreezeContext.freezeEventId` |
| `owner_vote_meeting_id = FreezeContext.meetingId` |
| `property_id = FreezeContext.propertyId` |
| `frozen_at = FreezeContext.freezeBoundaryAt` |

Shared with IU-2.1: same attempt identity · transaction ownership · atomic work envelope.

Cross-event, cross-meeting, cross-property, or reconstructed correlation is **prohibited**.

---

## 14. Parent contract for IU-2.3

Successful IU-2.2 materialization exposes **`resolutionSnapshotId`**.

IU-2.3 **must** consume this identity as the **exclusive** parent of every Frozen Motion for the Freeze Event:

```
Frozen Motion → resolutionSnapshotId → Freeze Event
```

IU-2.3 **must not:** create alternate Resolution Snapshot · select another parent · regenerate parent identity · bind to unrelated header · reconstruct parent from live state.

The IU-2.2 parent contract is **authoritative**.

---

## 15. Immutability baseline

Event-linked Resolution Snapshot rows participate in the E-01-certified immutability model.

IU-2.2 follows an **INSERT-oriented** materialization model.

After commit, the Resolution Snapshot **must not** be silently updated, deleted, rebuilt, replaced, or re-correlated.

Post-commit correction or reissue belongs to **E-06**. IU-2.2 does **not** introduce a competing correction mechanism.

## 17. Completeness baseline

**RESOLUTION_MATERIALIZED** means:

| Requirement |
|-------------|
| Authoritative source valid |
| One Resolution Snapshot header staged |
| Identity generated |
| One-to-one Freeze Event binding verified |
| Meeting/property/event correlation passed |
| Freeze-time consistency passed |
| `resolutionSnapshotId` available for IU-2.3 |

It does **not** mean the complete Phase 2 frozen instrument set exists.

**RESOLUTION_MATERIALIZED ≠ COMMIT_READY ≠ COMMITTED**

**MI-3** remains only partially satisfied after IU-2.2. Full Phase 2 materialization completeness requires **IU-2.3** Frozen Motion Materialization.

---

## 18. Failure and rollback baseline

IU-2.2 participates in the Phase 1-certified atomic work envelope.

Any IU-2.2 failure **must:**

| Requirement |
|-------------|
| Fail closed |
| Propagate to transaction owner |
| Prevent IU-2.3 hand-off |
| Prevent **COMMIT_READY** |
| Trigger Phase 1 rollback contract |

Rollback **must** remove all staged work within the same attempt, including prior IU-2.1 Voter Snapshot materialization.

No durable partial combination such as *Voter Snapshot + missing Resolution Snapshot* may survive a failed freeze attempt.

IU-2.2 does **not** own an independent transaction or independent commit.

---

## 19. Idempotency baseline

Phase 1 remains authoritative for freeze-level idempotency.

| Phase 1 outcome | IU-2.2 behavior |
|-----------------|-----------------|
| **IDEMPOTENT RETURN** | IU-2.2 does not execute |
| **RETRYABLE** | IU-2.2 does not execute |

IU-2.2 **must not** independently resolve committed-primary conflicts or competing transaction ownership.

After a valid post-rollback retry, the new attempt follows Phase 1 identity and transaction rules.
