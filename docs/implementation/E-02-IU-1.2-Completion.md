## 4. Validation baseline

IU-1.2 establishes the following **engineering baseline**.

### VALID

| Field | Definition |
|-------|------------|
| **Meaning** | All permanent preconditions are satisfied and no freeze condition prevents progression |
| **Effect** | Candidate Freeze Event identity **may** be assigned |
| **Next** | Hand off to **IU-1.3** Transaction Boundary |

### INVALID

| Field | Definition |
|-------|------------|
| **Meaning** | A permanent architectural, meeting, or required precondition fails |
| **Effect** | Fail closed. No candidate identity. No transaction. |

### IDEMPOTENT RETURN

| Field | Definition |
|-------|------------|
| **Meaning** | A committed primary Freeze Event already exists |
| **Effect** | Return the existing authoritative Freeze Event. **Do not** create a new Freeze Event identity. **Do not** treat as implementation failure. |

### RETRYABLE

| Field | Definition |
|-------|------------|
| **Meaning** | A transient condition prevents safe progression — includes: concurrent non-terminal attempt; transient transaction ownership; transient infrastructure or locking condition |
| **Effect** | Current attempt does not proceed. No new durable Freeze Event identity. Caller may retry. |

### CONFLICT

| Field | Definition |
|-------|------------|
| **Meaning** | Reserved for a durable state conflict that cannot be interpreted as INVALID, RETRYABLE, or IDEMPOTENT RETURN |
| **Phase 1** | No active CONFLICT emission case defined. No artificial conflict condition shall be introduced solely to exercise this outcome. |


## 6. Hand-off contract

Only **VALID** may proceed through:

```
Validation
        ↓
      VALID
        ↓
Candidate Freeze Identity
        ↓
IU-1.3 Freeze Transaction Boundary
```

| Outcome | Identity / transaction rule |
|---------|----------------------------|
| **INVALID** | Shall not assign identity |
| **RETRYABLE** | Shall not assign durable identity |
| **IDEMPOTENT RETURN** | Shall reuse existing committed primary identity |
| **CONFLICT** | Shall fail closed if emitted by a future authorized contract extension |

## 14. Knowledge captured

| Principle | Statement |
|-----------|-----------|
| Decision boundary | Freeze Validation is a **deterministic, side-effect-free** decision boundary |
| Ordering | Validation **precedes** candidate Freeze Event identity assignment |
| Idempotency | A previously committed freeze is an **idempotent success condition**, not a new freeze attempt |
| Contention | Transient contention is **retryable** and does not create durable identity |
| Scope limit | Validation does **not** own snapshot persistence, transaction opening, or commit |
