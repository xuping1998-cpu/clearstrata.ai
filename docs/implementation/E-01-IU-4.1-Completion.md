## 3. Repository interfaces

### `FrozenMeetingBundleRepository`

| Method | Description |
|--------|-------------|
| `loadByOwnerVoteMeetingId(id)` | Load meeting; resolve primary freeze event if present; legacy voter rows by `meeting_id` when no event |
| `loadByFreezeEventId(id)` | Fail closed when event missing; load correlated dual snapshot |

### Factory / singleton

| Export | Purpose |
|--------|---------|
| `createFrozenMeetingBundleRepository({ client? })` | Injectable client for tests |
| `frozenMeetingBundleRepository` | Default singleton |

### Standalone functions

- `loadFrozenMeetingBundleByOwnerVoteMeetingId`
- `loadFrozenMeetingBundleByFreezeEventId`

## 5. Repository methods — load order

```
Meeting
  ↓
Primary Freeze Event (optional)
  ↓
Voter Snapshot (by freeze_event_id or legacy meeting_id)
  ↓
Resolution Snapshot (when freeze event present)
  ↓
Frozen Motions (when freeze event present)
```

Repository operations: **SELECT → validate → map → correlate → return** only.

---

## 6. Legacy compatibility

| Scenario | Behavior |
|----------|----------|
| Production rows with `freeze_event_id IS NULL` | `readMode: 'legacy_meeting'`; voters loaded by `meeting_id` |
| Primary freeze event present | `readMode: 'event_linked'`; voters filtered by `freeze_event_id` |
| Resolution / motions empty | Returns `null` / `[]` until E-02 population |
| Missing meeting / freeze event (by id) | Fail closed with typed error |
