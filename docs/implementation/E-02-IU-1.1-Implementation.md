## 1. Purpose

Define the **implementation design** for **IU-1.1 — Freeze Event Creation**.

IU-1.1 **shall establish** the **architectural correlation root** used by all downstream E-02 phases. Implementation **shall not** materialize snapshots. Implementation **shall not** perform commit.

This document implements [`E-02-Phase-1-Implementation-Plan.md`](E-02-Phase-1-Implementation-Plan.md) §IU-1.1 and **shall not redefine** architecture decisions in [`E-02-Architecture.md`](E-02-Architecture.md).

## 5. Architecture constraints

IU-1.1 implementation **shall preserve**:

| Constraint set | Requirement |
|----------------|-------------|
| **Freeze Authority FA-1–FA-4** | Identity creation does not substitute for authorization; fail closed if identity cannot be assigned safely |
| **Correlation Model CM-1–CM-7** | Root id designed for 1:1 event↔snapshots; no cross-event binding |
| **Recovery Model RM-1–RM-5** | Candidate/abandoned identities never become repair paths for committed state |
| **Freeze Contract** | Freeze Event is mandatory output identity; inputs (Meeting) supply meeting scope only |
| **Program Invariants PI-1–PI-5** | Single identity · single boundary context · fail closed · no partial freeze · **no snapshot persistence** |

## 6. Implementation design

Design only — **no implementation code**, SQL, or RPC signatures.

### 6.1 Identity generation

| Rule | Design |
|------|--------|
| **Generator** | Platform-standard globally unique identifier (UUID v4 or equivalent) assigned at freeze attempt start |
| **When assigned** | Immediately after IU-1.2 validation passes and before Phase 2 materialization begins — within orchestration `FreezeContext` |
| **Scope binding** | Candidate identity is bound to exactly one `ownerVoteMeetingId` and one `propertyId` for the attempt |
| **Primary flag** | Candidate is marked **primary** for this meeting freeze boundary; non-primary events are out of IU-1.1 scope (E-06 correction) |
| **Persistence timing** | Candidate id may exist in orchestration memory first; durable row insert occurs inside transaction boundary (IU-1.3) — **commit** of row is Phase 3 |

**E-01 foundation consumed:** Persistence target entity `owner_vote_freeze_events` with fields aligned to domain type `FreezeEvent` ([`src/lib/ownerVote/snapshotDomain/types.ts`](../../src/lib/ownerVote/snapshotDomain/types.ts) — read-only reference, not modified in IU-1.1).

### 6.2 Identity lifecycle

```
Unassigned
    ↓ (validation passed — IU-1.2)
Candidate
    ↓ (transaction open — IU-1.3)
Staged
    ↓ (Phase 3 commit)          ↓ (rollback / abandon)
Committed Primary              Abandoned
    (terminal)                    (terminal for this attempt)
```

| State | Meaning | Durable? |
|-------|---------|----------|
| **Unassigned** | No freeze attempt identity yet | No |
| **Candidate** | UUID assigned; held in orchestration context | No |
| **Staged** | Identity associated with open transaction; row may be inserted uncommitted | Uncommitted only |
| **Committed Primary** | Primary freeze event row committed — correlation root for all artifacts | Yes (Phase 3) |
| **Abandoned** | Attempt ended without commit; identity must not be reused as silent rebuild | No durable primary |

**IU-1.1 delivers:** design and orchestration contract for **Unassigned → Candidate → Staged** entry. **Committed Primary** and **Abandoned** terminal transitions are specified here but **executed** in IU-1.3 / Phase 3.

**Immutable identity lifecycle (R-003 mitigation):** Once **Committed Primary**, the event id **shall not** be repurposed. A new freeze attempt after rollback receives a **new** candidate id. Correction/reissue creates a **new** event identity under E-06 — never overwrites committed id (INV-8, RM-3, RM-5).

### 6.3 Identity ownership

| Owner | Responsibility |
|-------|----------------|
| **Freeze Engine orchestration** | Assigns candidate id; carries `FreezeContext.freezeEventId` through Phases 1–3 |
| **E-01 persistence layer** | Hosts `owner_vote_freeze_events` row on commit; enforces primary uniqueness per meeting |
| **IU-1.2 validation** | Confirms no conflicting committed primary before assignment |
| **IU-1.3 transaction boundary** | Owns staged row lifecycle within open transaction |
| **E-01 typed repository** | Reads committed event post Phase 3/4 — does **not** assign ids (Repository First) |

**Correlation ownership (R-002 mitigation):** The orchestration context is the **sole writer** of the candidate root id into downstream staging structures. Phase 2 materialization **shall** read `freezeEventId` from context — never invent a parallel id.

### 6.4 Identity visibility

| Consumer | Visibility | Phase |
|----------|------------|-------|
| **Freeze orchestration internals** | Full candidate/staged id | 1–3 |
| **IU-1.2 validation** | Read committed primary ids for conflict check | 1 |
| **Phase 2 materialization** | Receives root id via context | 2 |
| **Phase 3 commit** | Persists and finalizes primary event | 3 |
| **E-01 repository (`FrozenMeetingBundle`)** | Reads committed `FreezeEvent` only | 4 |
| **Voting / UI** | No visibility until post-commit authorized read paths | E-03+ |

Candidate and staged identities **shall not** leak to voting gates or public API responses.

### 6.5 Identity state (orchestration model)

Orchestration **shall** expose a typed **Freeze Event identity state** on `FreezeContext`:

| Field | Purpose |
|-------|---------|
| `freezeEventId` | Candidate or staged UUID |
| `identityState` | `unassigned` · `candidate` · `staged` · `committed` · `abandoned` |
| `ownerVoteMeetingId` | Meeting scope |
| `propertyId` | Tenant scope |
| `isPrimary` | Always `true` for IU-1.1 scope |
| `assignedAt` | Freeze-instant timestamp (logical; set at assignment) |

State transitions **shall** align with Architecture Authority freeze state machine §12: identity assignment occurs during transition to **Preparing → Materializing**.

### 6.6 Correlation mapping

**Root mapping** — all event-linked artifacts **shall** reference the same `freezeEventId`:

```
FreezeEvent (root)
    ├── VoterSnapshotEntry[]     (Phase 2 — CM-1)
    ├── ResolutionSnapshot       (Phase 2 — CM-2)
    └── FrozenMotion[]           (Phase 2 — CM-3)
            └── via resolutionSnapshotId → ResolutionSnapshot
```

| Mapping rule | Enforcement |
|--------------|-------------|
| CM-4 | Every persisted artifact carries `freezeEventId` |
| CM-5 | Staging structures reject mismatched event ids |
| CM-6 | Phase 3 commit rejected if any staged artifact lacks root binding |
| CM-7 | Repository bundle loader validates correlation on read (Phase 4) |

**Legacy path:** Rows with `freezeEventId = null` remain valid; IU-1.1 does **not** assign ids to legacy rows (PI-5, backward compatibility).

### 6.7 Identity validation

| Check | When | On failure |
|-------|------|------------|
| No committed primary for meeting boundary | Before Candidate assignment | Idempotent return or fail closed (R-001) |
| Meeting id + property id consistent | Before assignment | Fail closed |
| Candidate UUID non-null and well-formed | After generation | Fail closed |
| Single active candidate per meeting attempt | During staging | Conflict → Cancelled / Failed (R-003) |

Full architectural precondition validation (authorization, resolution completeness) belongs to **IU-1.2** — IU-1.1 defines only **identity-specific** validation.

### 6.8 Uniqueness strategy

| Layer | Strategy |
|-------|----------|
| **Generation** | UUID collision probability negligible; no application-level reuse pool |
| **Meeting boundary** | At most one **committed primary** freeze event per meeting (E-01 partial unique index policy) |
| **Concurrent attempts** | First stager wins; others detect existing staged/committed primary (R-001, R-003) |
| **Post-commit** | Repeat invoke returns existing committed event id — no new primary (INV-8 idempotency — Phase 3) |
| **Correction** | New event id under E-06 — never reuses committed primary id as rebuild |

## 9. Engineering risks

| ID | Risk | Mitigation |
|----|------|------------|
| **R-001** | **Duplicate identity** | Uniqueness strategy §6.8; committed-primary check before assignment; idempotent path for repeat invoke |
| **R-002** | **Lost correlation** | Correlation ownership §6.3 — single `FreezeContext` carries root id; Phase 2 reads from context only |
| **R-003** | **Identity reuse** | Immutable lifecycle §6.2 — new attempt → new candidate; committed ids never repurposed; E-06 for correction |
