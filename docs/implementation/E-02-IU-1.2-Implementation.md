## 1. Purpose

Define the **implementation design** for **IU-1.2 — Freeze Validation**.

IU-1.2 **shall determine** whether a **Freeze Transaction may begin**. IU-1.2 **shall validate architectural preconditions only** — not authorization policy (FA-1, FA-2) and not workflow execution.

IU-1.2 **shall not** materialize snapshots, perform commit, or execute upstream workflow (scheduler, council UI, recovery orchestration).

This document implements [`E-02-Phase-1-Implementation-Plan.md`](E-02-Phase-1-Implementation-Plan.md) §IU-1.2 and **shall not redefine** architecture decisions in [`E-02-Architecture.md`](E-02-Architecture.md).

## 3. Objective

Validate all **architectural preconditions** required before opening a Freeze Transaction.

| Output | Description |
|--------|-------------|
| **Freeze Validation Result** | Deterministic single outcome — gate for identity assignment (IU-1.1 runtime) and transaction open (IU-1.3) |

**Success path:** `VALID` → orchestration may assign candidate Freeze Event identity and proceed to IU-1.3 transaction boundary.

**Failure paths:** `INVALID` · `CONFLICT` · `RETRYABLE` → **no** transaction open; **no** snapshot persistence (PI-5).

---

## 4. Validation scope

### In scope

| Area | Validates |
|------|-----------|
| **Meeting existence** | Target meeting record resolvable for freeze attempt |
| **Meeting lifecycle state** | Meeting in authoring / freeze-eligible phase per Architecture Authority |
| **Freeze eligibility** | Resolution set completeness pre-check; membership readable at freeze instant (read only) |
| **Freeze ownership context** | Authorization **context present** (not policy decision — FA-1) |
| **Existing committed Freeze Event** | Primary committed event detection for idempotency / conflict (RA-004) |
| **Concurrent freeze detection** | Active in-flight attempt on same meeting boundary |
| **Correlation integrity** | Meeting id ↔ property id consistency; context fields coherent |
| **Transaction readiness** | All prior validation stages pass; safe to hand off to IU-1.3 |

### Out of scope

| Item | Owner |
|------|-------|
| Snapshot persistence | Phase 2 |
| Resolution Snapshot / Frozen Motions materialization | Phase 2 |
| Commit | Phase 3 |
| Primary Audit | Phase 3 |
| **Voting eligibility** | E-03 |
| Authorization policy (who may invoke freeze) | Upstream workflow (E-04) |
| Repository adoption | Phase 4 |
| Consumer wiring | E-04 + authorized work |

## 5. Validation contract

Freeze Validation **shall return exactly one** `FreezeValidationResult`. **No partial validation state** shall be exposed to callers.

### Outcomes

| Outcome | Meaning |
|---------|---------|
| **VALID** | All architectural preconditions satisfied — transaction may open |
| **INVALID** | Preconditions failed — fail closed; no retry without upstream change |
| **CONFLICT** | Committed primary exists or concurrent winner — idempotent return or explicit conflict per RA-004 |
| **RETRYABLE** | Transient read failure or timing condition — upstream may retry (RM-2) |

### Result structure

Every outcome **shall** include:

| Field | Requirement |
|-------|-------------|
| **Decision** | One of `VALID` · `INVALID` · `CONFLICT` · `RETRYABLE` |
| **Reason** | Stable machine-readable code + human-readable summary |
| **Blocking condition** | Primary failed check (null when `VALID`) |
| **Recommended next action** | Orchestration hint — e.g. `OPEN_TRANSACTION` · `RETURN_EXISTING_FREEZE` · `ABORT` · `RETRY` |

**Example mapping** *(informative — not error catalog)*:

| Condition | Outcome | Recommended next action |
|-----------|---------|-------------------------|
| All checks pass | VALID | `OPEN_TRANSACTION` |
| Meeting not in authoring | INVALID | `ABORT` |
| Resolution incomplete | INVALID | `ABORT` |
| Committed primary exists | CONFLICT | `RETURN_EXISTING_FREEZE` (RA-004 policy) |
| Concurrent in-flight freeze | CONFLICT | `ABORT` or `RETRY` per policy |
| Membership read timeout | RETRYABLE | `RETRY` |
| Authorization context absent | INVALID | `ABORT` (FA-4) |

---

## 6. Validation model

Validation **shall execute in deterministic order**. Early exit on first blocking failure unless stage explicitly allows accumulation for diagnostics (internal only — external result remains single outcome).

```
1. Meeting validation
        ↓
2. Freeze state validation
        ↓
3. Correlation validation
        ↓
4. Conflict validation
        ↓
5. Transaction readiness
        ↓
FreezeValidationResult (exactly one)
```

### Stage definitions

| Stage | Checks | Fail closed |
|-------|--------|-------------|
| **1. Meeting validation** | Meeting exists; property scope resolvable; meeting not deleted/archived | ✓ |
| **2. Freeze state validation** | Lifecycle phase freeze-eligible; not post-commit frozen; resolution set non-empty and structurally valid; membership readable | ✓ |
| **3. Correlation validation** | `ownerVoteMeetingId` + `propertyId` consistent; `FreezeContext` fields coherent with meeting | ✓ |
| **4. Conflict validation** | No committed primary freeze for boundary **or** CONFLICT path; no blocking concurrent attempt | ✓ |
| **5. Transaction readiness** | Authorization context present; validation state `pending` → `passed`; hand-off token for IU-1.3 | ✓ |

**Identity assignment timing:** On **VALID** only, orchestration **may** invoke IU-1.1 identity assignment (Candidate state) before IU-1.3 opens transaction — consistent with IU-1.1 Design Review RA-001.

---

## 7. Architecture constraints

IU-1.2 **shall preserve**:

| Constraint set | Application in IU-1.2 |
|----------------|------------------------|
| **FA-1 – FA-4** | Validates authorization **context** presence only; does not determine caller permission; fail closed on absent context |
| **CM-1 – CM-7** | Correlation validation stage; no artifact creation |
| **RM-1 – RM-5** | INVALID/CONFLICT/RETRYABLE prevent transaction open — no rollback needed (nothing committed) |
| **Freeze Contract** | Validates inputs (Meeting, Membership, Resolutions readable); does not produce outputs |
| **PI-1 – PI-5** | No identity assignment on INVALID; no snapshot persistence; single decision |

---

## 8. FreezeContext contract

| Rule | Requirement |
|------|-------------|
| **Consumes** | `FreezeContext` from IU-1.1 — meeting scope, property scope, optional pre-assigned identity fields |
| **May update** | **Validation state only** — e.g. `validationState`: `pending` · `passed` · `failed` · `conflict` |
| **Must NOT modify** | `freezeEventId` · `identityState` (identity assignment occurs only after VALID — IU-1.1 orchestration step) |

### Validation state fields *(additive to IU-1.1 context)*

| Field | Purpose |
|-------|---------|
| `validationState` | Current validation lifecycle on context |
| `validationResult` | Last `FreezeValidationResult` (when complete) |
| `validatedAt` | Timestamp validation completed |

## 9. Engineering risks

| ID | Risk | Mitigation |
|----|------|------------|
| **R-005** | Incorrect validation order | Deterministic pipeline §6 — fixed stage sequence |
| **R-006** | Partial validation exposed | Single `FreezeValidationResult` contract §5 |
| **R-007** | Conflicting readiness signals | Single decision authority — one outcome enum only |

Phase 1 plan risks **R-002** (invalid meeting state) and **R-001** (duplicate freeze) are addressed in stages 2 and 4 respectively.
