## 1. Purpose

Define the **engineering implementation design** for **E-02 IU-3.3 — Idempotent Retry**.

IU-3.3 **shall** close Phase 3 by defining how the freeze engine safely handles:

| # | Scenario |
|---|----------|
| 1 | Already committed authoritative Freeze Event |
| 2 | Active competing attempt |
| 3 | Failed / rolled-back attempt |
| 4 | Concurrent freeze attempts |
| 5 | Retry after rollback |
| 6 | Duplicate invocation |
| 7 | Final commit orchestration |

When all authoritative gates pass, IU-3.3 defines the semantic path:

```
AUDIT_PREPARED → Final Commit Eligibility → Database COMMIT → COMMITTED
```

This Implementation Design **does not execute** any COMMIT.

IU-3.3 **shall not:** repair Phase 1 / Phase 2 / IU-3.1 / IU-3.2 · create Primary Audit persistence · redefine closed ACQ / AQ / PA / AI semantics · update `owner_vote_meetings.status` · invoke legacy freeze RPC.

## 4. Objective

**Consume IU-3.2 `AUDIT_PREPARED` → resolve idempotency / concurrency → authorize final commit when eligible → define `COMMITTED` terminal semantics — without executing DB COMMIT in this document.**

```
AUDIT_PREPARED
        ↓
Idempotency / ownership / concurrency resolution
        ↓
Final commit authorization (when eligible)
        ↓
Database COMMIT (executable layer only)
        ↓
COMMITTED
```

**IU-3.3 local terminal success (when commit path executes):** **`COMMITTED`**

**Alternative authoritative terminal outcomes:** **`IDEMPOTENT_RETURN`** · **`RETRYABLE`** · **`NEW_ATTEMPT_REQUIRED`** (and failure variants — §15)

**Normative separation:**

```
AUDIT_PREPARED ≠ COMMITTED
Pre-commit staged A–G ≠ COMMITTED
Client success acknowledgement ≠ COMMITTED
```

## 5. Entry contract

### 5.1 Normal final-commit path entry

IU-3.3 final-commit orchestration may enter **only** when **all** conditions hold:

| Condition | Requirement |
|-----------|-------------|
| Valid `FreezeContext` | Present |
| Phase 1 validation | **VALID** (or idempotency branch resolved first — §6) |
| Authoritative transaction ownership | Current caller owns active envelope |
| Active Phase 1 atomic envelope | Open |
| IU-3.1 result | **COMMIT_PREPARED** |
| IU-3.2 result | **AUDIT_PREPARED** |
| Atomic Commit Set | **A – G** complete |
| Phase 2 materialization | Complete |
| Correlation | Verified — same `freezeEventId` · `meetingId` · `propertyId` · attempt · `freezeBoundaryAt` |
| Superseding committed primary | **None** (or resolved via **IDEMPOTENT RETURN** before commit path) |
| Primary Audit persistence prerequisite | Satisfied at **executable implementation time** — **BLOCKED until then** |

Any failure: **FAIL CLOSED**.

**Prohibited:**

| Prohibition |
|-------------|
| Repair Phase 1 / Phase 2 / IU-3.1 / IU-3.2 |
| Re-materialize snapshots |
| Re-stage marker / audit from live sources |
| Open second commit transaction for same authoritative freeze |

### 5.2 Early idempotency gate entry

IU-3.3 idempotency resolution **may** execute **before** full Phase 3 commit path when Phase 1 / Phase 3 entry detects:

| Condition | Outcome |
|-----------|---------|
| Authoritative committed primary already exists for meeting | **IDEMPOTENT RETURN** |
| Active competing attempt owns boundary | **RETRYABLE** |
| Prior attempt rolled back · no committed primary · no active owner | **NEW ATTEMPT REQUIRED** — re-enter Phase 1 |

Phase 1 certified semantics preserved: **IDEMPOTENT RETURN** and **RETRYABLE** **do not** open a new transaction (IU-1.3 Completion baseline).

## 6. Three authoritative idempotency outcomes

### 6.1 IDEMPOTENT RETURN

**Conditions:**

| Gate |
|------|
| Target meeting has authoritative **committed** primary Freeze Event |
| Invocation semantics correspond to that committed freeze |
| Durable A–G evidence reconciles to single authoritative commit |

**Behavior:**

| Action | Rule |
|--------|------|
| Re-materialize | **Prohibited** |
| Re-stage marker | **Prohibited** |
| Create second Primary Audit | **Prohibited** |
| Execute second DB COMMIT | **Prohibited** |
| Modify frozen artifacts | **Prohibited** |
| New `freezeEventId` | **Prohibited** |
| Return | Authoritative committed identity / result |

**Minimum authoritative return evidence:**

| Element |
|---------|
| Original committed `freezeEventId` |
| `meetingId` · `propertyId` |
| Committed `freezeBoundaryAt` |
| Committed primary audit identity (when persistence exists) |
| Outcome = **IDEMPOTENT_RETURN** |
| Indication that durable committed state already exists |

```
IDEMPOTENT RETURN ≠ RETRYABLE
IDEMPOTENT RETURN ≠ COMMITTED (new commit)
IDEMPOTENT RETURN ≠ FAILURE
```

### 6.2 RETRYABLE

**Conditions:**

| Gate |
|------|
| Another **active / in-flight** attempt holds authoritative transaction ownership |
| **No** committed primary available for **IDEMPOTENT RETURN** |
| Current caller does **not** own the boundary |

**Behavior:**

| Action | Rule |
|--------|------|
| Preempt ownership | **Prohibited** |
| Execute Phase 2 / Phase 3 staging | **Prohibited** |
| Create competing Primary Audit | **Prohibited** |
| COMMIT | **Prohibited** |
| Return | **RETRYABLE** — caller may retry later |

```
RETRYABLE ≠ FAILURE OF COMMITTED STATE
RETRYABLE ≠ IDEMPOTENT RETURN
RETRYABLE ≠ NEW_ATTEMPT_REQUIRED (when active owner still holds boundary)
```

**Terminal classification:** **Non-terminal** for caller — retry permitted after contention clears.

### 6.3 NEW ATTEMPT AFTER ROLLBACK

**Conditions:**

| Gate |
|------|
| Prior attempt failed and completed rollback |
| **No** authoritative committed primary |
| **No** still-active competing owner |

**Behavior:**

| Action | Rule |
|--------|------|
| Reuse abandoned `freezeEventId` | **Prohibited** |
| Reuse abandoned `primaryAuditId` | **Prohibited** |
| Resume from **COMMIT_PREPARED** / **AUDIT_PREPARED** of old attempt | **Prohibited** |
| New attempt identity | **Required** |
| New `freezeEventId` | **Required** |
| New eventual `primaryAuditId` | **Required** |
| Re-entry point | Phase 1 validation / transaction lifecycle |

```
ROLLED_BACK attempt is terminal for that identity.
```

**Terminal classification:** **Terminal for old identity** · **Non-terminal for freeze operation** — new attempt may proceed.

## 7. IDEMPOTENT RETURN contract

### 7.1 Committed-primary detection

Authoritative committed-primary detection **shall** consider:

| Evidence class | Role |
|----------------|------|
| Durable primary Freeze Event row | `owner_vote_freeze_events` where correlation proves committed primary |
| `is_primary = true` | Necessary but **not sufficient alone** |
| Partial unique index | `owner_vote_freeze_events_one_primary_per_meeting` — prevents duplicate primary per meeting |
| Durable snapshot set | Event-linked B–D rows |
| Durable freeze marker | `snapshot_frozen_at` populated and aligned |
| Durable Primary Audit | Artifact G row (when persistence exists) — **UNIQUE(freeze_event_id)** |
| A–G correlation intact | Same event · meeting · property · boundary |
| Successful DB COMMIT | **Necessary** — staging alone insufficient |

### 7.2 Distinction requirements

IU-3.3 **must** distinguish:

| State | Detection challenge |
|-------|---------------------|
| Staged primary inside current uncommitted envelope | Same txn — not yet durable |
| Durable committed primary | Post-COMMIT composite evidence |
| Abandoned / rolled-back identity | No durable marker + no durable audit + txn aborted |
| Competing active attempt | Phase 1 ownership metadata |

**Repository gap:** No explicit `commit_state` / `committed_at` on `owner_vote_freeze_events`. **Must not invent** undocumented columns. Composite durable-state reconciliation required — **IQ-001** · **IQ-002**.

Primary Audit `committed_at` or equivalent (when implemented) **may** participate as commit evidence component — **IQ-003** — but physical target **PENDING**.

## 8. COMMITTED authority contract

### 8.1 What proves COMMITTED

**COMMITTED** requires **all** of the following durable evidence:

| # | Evidence |
|---|----------|
| 1 | Authoritative primary Freeze Event **durable** (not merely staged in open txn) |
| 2 | Authoritative snapshot set **durable** (B–D) |
| 3 | Freeze marker **durable** (`snapshot_frozen_at` + aligned `frozen_at`) |
| 4 | Primary Audit **durable** (Artifact G) |
| 5 | A–G correlation **intact** |
| 6 | Exactly-one constraints satisfied (primary per meeting · audit per freeze event) |
| 7 | Database transaction **successfully committed** |

### 8.2 Insufficient sole authority

The following **shall not alone** prove **COMMITTED**:

| Insufficient alone |
|--------------------|
| `is_primary = true` |
| `snapshot_frozen_at` populated |
| `frozen_at` |
| `created_at` |
| **AUDIT_PREPARED** |
| **COMMIT_PREPARED** |
| A–G staged completeness inside open transaction |
| Client / RPC success response |

### 8.3 Schema gap (design question)

Current migration head lacks explicit commit-state metadata on Freeze Event row.

| Classification | **IQ-001 / CQ extension for Design Review** |
|----------------|-----------------------------------------------|
| Resolution path | Composite durable reconciliation algorithm + Primary Audit commit evidence slot |
| Prohibited | Fabricate undocumented `status` / `committed_at` on `owner_vote_freeze_events` in this design |

## 9. Final commit orchestration

Conceptual orchestration — **no executable SQL**.

```
AUDIT_PREPARED
        ↓
Revalidate ownership
        ↓
Revalidate no committed / superseding primary
        ↓
Verify A–G completeness
        ↓
Verify Primary Audit staged (G)
        ↓
Verify freeze marker staged (E)
        ↓
Verify correlation (event · meeting · property · attempt · boundary)
        ↓
Verify persistence prerequisites (Artifact G target exists at executable time)
        ↓
Final commit authorization
        ↓
DB COMMIT
        ↓
COMMITTED
```

| Rule | Requirement |
|------|-------------|
| Successful DB COMMIT | **Necessary** for **COMMITTED** |
| Pre-commit states | **Must never** return **COMMITTED** |
| Post-COMMIT | Emit **COMMITTED** only after durable reconciliation confirms success |

**Executable prerequisite gate:** If Primary Audit persistence target absent → final commit path **BLOCKED** — return **COMMIT_PRECONDITION_FAILURE** (or equivalent) — not **COMMITTED**.

## 10. Commit failure semantics

If final DB COMMIT fails:

| Rule | Requirement |
|------|-------------|
| **COMMITTED** emission | **Prohibited** |
| Attempt lifecycle | Transition through rollback / failure semantics |
| Partial durable freeze | **Not accepted** |
| Retry with abandoned `freezeEventId` | **Prohibited** |
| Subsequent valid retry | New attempt identity · new `freezeEventId` · new `primaryAuditId` |

Full envelope rollback per Phase 1 owner — same scope as IU-3.1 / IU-3.2 baselines.

---

## 11. Commit-outcome-uncertain handling

**Problem:** Client / connection may lose acknowledgement around COMMIT boundary (sent COMMIT · response lost · connection dropped).

**Design requirement:** Subsequent invocation **must** reconcile via **authoritative durable state** — not client ack alone.

| Reconciliation result | Outcome |
|-----------------------|---------|
| Durable committed A–G exists | **IDEMPOTENT RETURN** |
| Not committed + active owner holds boundary | **RETRYABLE** |
| Rolled back / no active owner | **NEW_ATTEMPT_REQUIRED** |

```
COMMIT_OUTCOME_UNCERTAIN → durable reconciliation → one of above
```

**Invariant II-9 / II-10:** Client acknowledgement is **not** commit authority.

Algorithm detail → **IQ-006** (Design Review).

## 12. Concurrency contract

Same-meeting concurrent freeze attempts:

| Scenario | Resolution |
|----------|------------|
| Attempt A holds authoritative ownership | Attempt B **must not** continue Phase 2 / Phase 3 |
| A eventually **COMMITTED** | B subsequent calls → **IDEMPOTENT RETURN** |
| A rollback | B or later invocation → **NEW ATTEMPT** with new ids |

**Consumed guards:**

| Guard | Source |
|-------|--------|
| Phase 1 transaction ownership | Phase 1 Certification |
| **RETRYABLE** semantics | Phase 1 / IU-1.3 |
| One-primary-per-meeting unique index | Repository |
| Primary Audit exactly-one-per-freeze-event | IU-3.2 baseline |

**Prohibited:**

| Prohibition |
|-------------|
| Dual primary |
| Dual audit |
| Dual marker authority |
| Dual commit |
| Competing materialization |
| Ownership stealing |

## 13. Duplicate invocation contract

Covers: same request twice · browser retry · network retry · RPC retry · worker retry · post-timeout retry · post-commit response loss.

| Durable state | Outcome |
|---------------|---------|
| Already committed | **IDEMPOTENT RETURN** |
| Active owner · not committed | **RETRYABLE** |
| Rolled back · no owner | **NEW_ATTEMPT_REQUIRED** |
| In-flight same owner · same attempt | Continue or reconcile — **must not** second-commit |

**Must not cause:** second freeze event · second primary audit · second snapshot set · second marker write · second COMMIT.

## 14. Identity non-reuse

| Identity | Lifecycle |
|----------|-----------|
| Attempt identity | Single-lifecycle |
| `freezeEventId` | Single-attempt identity |
| `primaryAuditId` | Single-attempt audit identity |

**After rollback:**

| Old identity | Status |
|--------------|--------|
| Old attemptId | **Terminal** |
| Old `freezeEventId` | **Abandoned — never reused** |
| Old `primaryAuditId` | **Abandoned — never reused** |

**New retry:**

| New identity | Required |
|--------------|----------|
| New attemptId | **Yes** |
| New `freezeEventId` | **Yes** |
| New `primaryAuditId` | **Yes** |

**Prohibited:** Resume rolled-back staged identity from **COMMIT_PREPARED** / **AUDIT_PREPARED**.

## 15. Result contract

| Outcome | Meaning | Terminal? | Caller may retry? | Same identity reuse? | Durable committed? |
|---------|---------|-----------|-------------------|----------------------|-------------------|
| **COMMITTED** | Final DB COMMIT succeeded; durable A–G | **Yes** | N/A (success) | N/A | **Yes** |
| **IDEMPOTENT_RETURN** | Committed primary already exists | **Yes** | Optional (same result) | Returns **existing** committed ids | **Yes** (pre-existing) |
| **RETRYABLE** | Active competitor holds ownership | **No** | **Yes** — later | **No** durable assignment | **No** |
| **NEW_ATTEMPT_REQUIRED** | Prior attempt terminal; new lifecycle needed | **Yes** (for old id) | **Yes** — new attempt | **No** — new ids required | **No** |
| **COMMIT_PRECONDITION_FAILURE** | Gate failed before COMMIT | **Yes** | Depends on cause | **No** if rolled back | **No** |
| **COMMIT_CONFLICT** | Unresolvable commit conflict | **Yes** | Reconcile first | **No** if rolled back | **No** |
| **COMMIT_FAILURE** | DB COMMIT failed | **Yes** | New attempt | **No** — new ids | **No** |
| **COMMIT_OUTCOME_UNCERTAIN** | Ack lost; reconciliation required | **No** | Reconcile then branch | TBD by reconciliation | **Unknown until reconciled** |
| **CORRELATION_FAILURE** | Id / correlation mismatch | **Yes** | Fix input / new attempt | **No** | **No** |
| **TRANSACTION_FAILURE** | Envelope / txn failure | **Yes** | New attempt after rollback | **No** | **No** |

```
RETRYABLE ≠ NEW_ATTEMPT_REQUIRED
```
