## 5. Central design question — proof summary

### 5.1 Mechanism triad

| Layer | Mechanism | Role |
|-------|-----------|------|
| **In-flight exclusion** | `pg_try_advisory_xact_lock(meeting_key)` | One active transaction owner per meeting |
| **Atomic materialization** | Single SECURITY DEFINER RPC — implicit PostgreSQL transaction | A–G all-or-nothing |
| **Durable authority** | Committed correlated A–G rows | Idempotency · lost-ack recovery · post-commit evidence |

### 5.2 Proof sketch

1. **Concurrent callers:** Second caller fails try-lock → **RETRYABLE** (ACE-3). No durable rows written.
2. **Connection loss / exception:** Transaction rollback releases xact lock automatically; no partial A–G survives (ACE-9, ACE-10).
3. **Commit success + lost response:** Lock already released; durable full A–G exists → reconciliation → **IDEMPOTENT_RETURN** (ACE-12, ACE-13).
4. **Retry after rollback:** No lock · no committed A–G → **NEW_ATTEMPT_REQUIRED** with Phase 1 new identities (ACE-11).
5. **Stale owner avoidance:** Xact lock cannot outlive transaction — no stale durable "active" flag (ACE-10).
6. **Original ID recovery:** Meeting → primary freeze event → `UNIQUE(freeze_event_id)` audit row → return stored IDs.
7. **Cross-meeting concurrency:** Meeting-scoped lock key — independent except rare hash collision (ACE-20).

### 5.3 Why durable ownership table is not required

See §10 — formal disposition **ERQ-1.2-005**.

## 9. Advisory lock model — ERQ-1.2-003 / ERQ-1.2-004 / ERQ-1.2-005

### 9.1 Proposed mechanism

| Field | Value |
|-------|-------|
| **Function** | `pg_try_advisory_xact_lock(bigint)` |
| **Scope** | One `owner_vote_meeting_id` per lock key |
| **Lifetime** | Transaction-scoped — automatic release on COMMIT or ROLLBACK |
| **Competitor behavior** | Lock unavailable → **RETRYABLE** — no wait |

### 9.2 Formal questions answered

| # | Question | Answer |
|---|----------|--------|
| 1 | Is transaction-scoped advisory lock sufficient for active in-flight ownership? | **YES** — exclusive holder within live PostgreSQL transaction satisfies Phase 1 / IU-3.3 one-owner semantics |
| 2 | Does automatic release satisfy no stale ownership? | **YES** — lock cannot survive connection loss, rollback, or commit |
| 3 | Does lock absence after transaction end create ambiguity? | **Only for in-flight vs idle** — resolved by try-lock at entry; **commit vs rollback** resolved by **durable A–G**, not lock |
| 4 | Can reconciliation distinguish committed vs rollback using durable A–G? | **YES** — full correlated A–G = committed candidate; absence = no committed envelope |
| 5 | Does this satisfy certified outcome mapping? | **YES** — see §15 |

| ERQ | Disposition |
|-----|-------------|
| **ERQ-1.2-003** | **RESOLVED** — hybrid: xact lock (in-flight) + durable A–G (committed) |
| **ERQ-1.2-004** | **RESOLVED** — advisory xact lock **semantically sufficient** for in-flight exclusion |

### 9.3 Lock availability classification (§21 authority)

| Signal | Classification |
|--------|----------------|
| Advisory lock held elsewhere | **TRANSIENT OWNERSHIP SIGNAL** |
| Lock availability | **NOT** durable committed evidence |
| Lock availability | **NOT** historical ownership record |
| Lock after txn end | **Absent by definition** — reconciliation uses durable rows only |

## 10. Durable ownership table necessity — ERQ-1.2-005

### 10.1 Options compared

| Option | Stale ownership | Crash cleanup | Uncertain commit | Retry classification | Extra complexity | Partial-state risk | Lifecycle cleanup | Identity history | Reconciliation usefulness |
|--------|----------------|---------------|------------------|---------------------|------------------|-------------------|-------------------|------------------|--------------------------|
| **A. No durable ownership table** | None — lock is txn-scoped | Automatic lock release | Durable A–G resolves | Certified table applies | **Lowest** | Prevented by single txn (ACE-9) | None required | Phase 1 owns history | Full A–G composite sufficient |
| **B. Dedicated ownership table** | **Risk** — stale "active" row without heartbeat | Manual/TTL cleanup required | Row + A–G redundant | Same outcomes achievable | High | Row + artifact split risk | Required | Duplicates Phase 1 | Redundant if A–G atomic |
| **C. Freeze event as ownership** | Pre-commit event possible on rollback | Rollback removes | Post-commit only | Insufficient in-flight | Medium | Partial event without G | None | Certified non-reuse applies | In-flight gap |
| **D. Hybrid persistent attempt row** | Same as B | Same as B | Same as B | Same as A with more surface | High | Higher | Required | Duplicates Phase 1 | Marginal |

### 10.2 Formal decision

| Decision | Value |
|----------|-------|
| **Durable ownership table** | **NOT REQUIRED** |
| **Proof** | In-flight exclusion = txn-scoped advisory lock. Committed state = durable correlated A–G. Rollback = no lock + no committed A–G. Lost ack = durable A–G lookup. No missing signal that a durable ownership row would provide without duplicating A–G or introducing stale-active risk. |
| **Missing signal test** | No implementer-critical signal identified that advisory lock + A–G cannot provide under certified IU-3.3 semantics. |

| ERQ | Disposition |
|-----|-------------|
| **ERQ-1.2-005** | **RESOLVED** — durable ownership table **NOT REQUIRED** |

## 11. Active owner semantics

**ACTIVE OWNER** (approved definition):

> A same-meeting PostgreSQL transaction that **currently holds** the approved meeting-scoped `pg_try_advisory_xact_lock` key **and has not yet committed or rolled back**.

| Property | Rule |
|----------|------|
| **Observable by competitor** | **YES** — via `pg_try_advisory_xact_lock` returning `false` |
| **Competitor outcome** | **RETRYABLE** |
| **Durable mirror flag** | **PROHIBITED** — do not create durable "active" row merely to reflect transient lock |
| **After commit** | Active owner **ceases** — committed A–G becomes durable evidence |
| **After rollback** | Active owner **ceases** — no durable owner |

## 12. Lock key design — ERQ-1.2-006

### 12.1 Options analyzed

| Option | Formula | Collision risk | Correctness impact | Disposition |
|--------|---------|----------------|-------------------|-------------|
| **A** | `hashtext(uuid::text)` | 64-bit hash space | False contention only | Acceptable but weaker distribution |
| **B** | `hashtextextended('e02_owner_vote_freeze:' \|\| uuid::text, 0)` | 64-bit hash space | False contention only | **APPROVED** |
| **C** | Split UUID into two int4 two-key lock | Lower collision | False contention only | Unnecessary complexity |
| **D** | Direct UUID bytes → int8 | Endian/truncation hazards | Theoretical conflation risk | **REJECTED** |
| **E** | Other | — | — | None superior identified |

### 12.2 Approved lock key

```sql
-- Design Review exact formula (Implementation Review must reproduce verbatim):
pg_try_advisory_xact_lock(
  hashtextextended('e02_owner_vote_freeze:' || p_owner_vote_meeting_id::text, 0)
)
```

### 12.3 Collision semantics (mandatory documentation)

| Scenario | Effect | Classification |
|----------|--------|----------------|
| Two **different** meetings hash to same 64-bit key | Unrelated meetings **serialize** briefly — one gets **RETRYABLE** | **Availability degradation only** |
| Same meeting concurrent attempts | Correct mutual exclusion | **Intended behavior** |
| Collision enables dual primary commit for **same** meeting | **IMPOSSIBLE** — same meeting → same UUID → same key |

**ACE-20 preserved:** Cross-meeting concurrency independent except extremely rare false contention.

| ERQ | Disposition |
|-----|-------------|
| **ERQ-1.2-006** | **RESOLVED** — `hashtextextended` with fixed namespace prefix |

| Mechanism | Competitor behavior | Certified fit |

## 14. Lock acquisition order — approved sequence

### 14.1 Approved orchestration sequence

| Step | Action | Early exit |
|------|--------|------------|
| **0** | Authenticate · authorize · resolve meeting/property server-side | FAILURE |
| **1** | **Initial reconciliation** (read-only durable evidence) | **IDEMPOTENT_RETURN** if full committed A–G |
| **2** | `pg_try_advisory_xact_lock(meeting_key)` | **RETRYABLE** if lock unavailable |
| **3** | **Committed double-check** (read-only — §15) | **IDEMPOTENT_RETURN** if committed A–G appeared |
| **4** | Validate Phase 1/3 supplied identities · prerequisites | FAILURE / **NEW_ATTEMPT_REQUIRED** |
| **5** | Materialize / verify A → B → C → D → F → E → G | Exception → full rollback |
| **6** | Final pre-return verification | Exception → full rollback |
| **7** | Return success payload (**≠ COMMITTED**) | — |

### 14.2 Race analysis

| Race | Mitigation |
|------|------------|
| Transaction A commits between step 1 and step 2 | Step 3 double-check catches committed A–G before materialization |
| Transaction A commits between step 2 and step 3 | Step 3 double-check before any INSERT |
| Duplicate freeze without double-check | **PREVENTED** by step 3 |

**Invariant added (approved):** **RU-1.2-DC-001** — After acquiring ownership lock, server **MUST** re-evaluate durable committed state before materializing new A–G.

## 18. Reconciliation model — ERQ-1.2-008

### 18.1 Authoritative evidence query (durable only)

**COMPLETE durable committed candidate** — **all** must hold:

| # | Evidence | Source |
