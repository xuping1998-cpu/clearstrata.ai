## 6. IQ-001 — Durable COMMITTED authority (highest priority)

**Question:** What evidence combination authoritatively determines Freeze Event = **COMMITTED** in current repository?

**Design Review resolution:**

| Layer | Verdict |
|-------|---------|
| **Design contract** | **VALID** — composite authority per Implementation §8.1 |
| **Runtime COMMITTED authority** | **BLOCKED / INCOMPLETE** until persistence prerequisites land |

**Authoritative composite (all required after successful DB COMMIT):**

| # | Evidence |
|---|----------|
| 1 | Durable primary Freeze Event |
| 2 | Durable snapshot set (B–D) |
| 3 | Durable freeze marker |
| 4 | Durable Primary Audit (Artifact G) |
| 5 | A–G correlation intact |
| 6 | Exactly-one constraints satisfied |
| 7 | Successful database transaction COMMIT |

**Critical rule:** Successful DB COMMIT is **necessary** but **not sufficient for later callers to infer COMMITTED from client ack alone**. Subsequent invocations **must** reconcile via **durable post-commit evidence** (II-9 · II-10).

**Repository gap:** Item 4 **cannot exist** at migration head. Items 1–3 may exist only after COMMIT — cannot distinguish staged vs durable without txn boundary + composite query.

| Classification | **RESOLVED** at design-contract level |
|----------------|---------------------------------------|
| Executable gate | **EXECUTABLE COMMITTED AUTHORITY INCOMPLETE** until Primary Audit migration + reconciliation EIR |

**Does not invalidate design approval.** **Does not claim runtime COMMITTED authority exists today.**

## 7. IQ-002 — Single-field insufficiency
