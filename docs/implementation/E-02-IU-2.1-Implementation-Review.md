### RA-2.1-001 — Duplicate contract

| Field | Value |
|-------|-------|
| **Status** | **RESOLVED** |
| **Authoritative rule** | Invalid duplicate = same `freezeEventId` + same normalized `unit_no` |
| **Valid multi-unit** | Same `user_id` across **different** normalized units is **VALID** when PEC selects rank-1 row per unit |

The original Implementation Design statement treating `freezeEventId + user_id` as invalid duplicate is **semantically superseded** by Design Review resolution. The Implementation document **shall not** be retroactively rewritten solely to hide this evolution. **This Implementation Review** and [`E-02-IU-2.1-Design-Review.md`](E-02-IU-2.1-Design-Review.md) govern duplicate semantics for IU-2.1 completion baseline.

## 8. Authoritative implementation contract (readiness baseline)

For IU-2.1 Completion and executable implementation, the following **authoritative** contracts apply:

| Contract | Rule |
|----------|------|
| **PEC source** | `property_members` — RC010-B §7.3 |
| **Eligible set** | Active owner/council with non-empty unit; rank-1 per `lower(trim(unit_no))`; council before owner |
| **Invalid duplicate** | Same `freezeEventId` + same normalized `unit_no` |
| **Valid multi-unit user** | Same `user_id`, different normalized units — each with PEC rank-1 row |
| **Success counts** | `sourceEligible = materializedTotal = materializedEligible`; `rejected = 0` |
| **Freeze instant** | Single `freezeBoundaryAt` → all `frozen_at` |
| **Legacy** | INSERT-only for current `freezeEventId`; no legacy mutation |
| **Success outcome** | **MATERIALIZED** only — not **COMMIT_READY** |

*Supersedes Implementation §10.1 / §27 VQ-005 `user_id` collision wording for semantics only.*
