## 4. Authoritative motion source baseline

**`public.owner_vote_resolutions`**

The source set **shall** be exactly the same qualifying set established by IU-2.2.

| Qualification rule | Requirement |

## 5. Motion cardinality baseline

```

        ↓

        ↓
```

IU-2.3 establishes strict source-motion coverage:

| Rule | Requirement |
|------|-------------|

## 16. Ordering baseline

Frozen Motion ordering must be deterministic.

| Rule | Requirement |
|------|-------------|
| 1 | Explicit source `display_order` values ordered ascending |
| 2 | NULL source ordering placed deterministically after explicitly ordered rows |
| 3 | Deterministic source identity tie-breaking for reproducible implementation ordering only |
| 4 | Final target `display_order` must satisfy target uniqueness |
| 5 | Duplicate explicit source orders that cannot validly satisfy target contract fail closed |

The tie-break does not introduce new business meaning. It exists only to make implementation deterministic.

This incorporates Design Review clarifications **C-4** and **C-5**.

---

## 17. Duplicate baseline

The authoritative invalid duplicate dimensions are:

### Duplicate source motion

Same **`resolution_snapshot_id`** + same **`source_resolution_id`**

### Duplicate final order

Same **`resolution_snapshot_id`** + same **`display_order`**

Both are invalid within one materialized Resolution Snapshot.

| Rule | Requirement |
|------|-------------|
| Duplicate state | Fail closed |
| Silent deduplication | Prohibited |
| Silent drop to satisfy uniqueness | Prohibited |

## 18. Motion count reconciliation baseline

Successful IU-2.3 materialization **shall** satisfy:

```
sourceMotionCount = frozenMotionCount
rejectedCount = 0
```

`sourceMotionCount` is the number of qualifying `owner_vote_resolutions` rows using the exact IU-2.2 qualification contract. It is not the raw count of unrelated Resolution rows.

Any omission · unexpected duplication · failed mapping · rejected qualifying row · or unexplained count drift prevents local materialization success.

## 19. Zero-motion baseline

A successful IU-2.3 materialization **shall** contain at least one Frozen Motion.

**Authoritative rule:** **Zero qualifying motions are not valid.**

Because IU-2.2 requires at least one qualifying Resolution row, IU-2.3 must materialize at least one corresponding Frozen Motion.

| Condition | Outcome |
|-----------|---------|
| Zero qualifying source motions | **MISSING_MOTION_SOURCE** or equivalent fail-closed result |

Zero Frozen Motions cannot satisfy **MOTIONS_MATERIALIZED**, MI-3, Phase 2 aggregate completeness, or **COMMIT_READY**.

## 26. Failure and rollback baseline

All IU-2.3 failures **fail closed**.

IU-2.3 does not own an independent rollback transaction.

Failure propagates to the Phase 1 transaction owner.

Rollback covers the complete materialization attempt:

```
staged IU-2.1 Voter Snapshot
+ staged IU-2.2 Resolution Snapshot
+ staged IU-2.3 Frozen Motions
```

No durable partial Phase 2 snapshot domain may survive a failed attempt.

There is no silent in-envelope retry.

There is no failure-to-success conversion.
