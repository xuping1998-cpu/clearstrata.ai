## 5. Authoritative eligibility baseline

The authoritative freeze-time voter source is:

**`public.property_members`**

under [`RC010-B-Production-Freeze-Contract-Recovery.md`](../rc/RC010-B-Production-Freeze-Contract-Recovery.md) §7.3 Production Eligibility Contract.

**Eligible source population:**

| Criterion | Requirement |
|-----------|-------------|
| Membership status | `active` |
| Role | `owner` or `council` |
| Unit | non-empty normalized unit |
| Selection | one rank-1 voter per normalized unit |

Where multiple eligible membership rows compete for the same normalized unit, **PEC ranking** applies. **Council outranks owner** for source-row selection.

IU-2.1 **shall not** introduce an alternative eligibility policy.

---

## 6. Rank-1 / role baseline

Exactly **one** authoritative rank-1 voter row is selected per normalized unit.

The materialized role **shall be** the role from the selected rank-1 source row. Role **shall not** be re-derived after ranking.

| Selected source row | Frozen role |
|---------------------|-------------|
| Council | `council` |
| Owner | `owner` |

The role records freeze-time source evidence. It does **not** itself constitute future ballot authorization. **E-03** owns ballot authorization.

---

## 7. Freeze-time baseline

The complete IU-2.1 voter set represents **one logical freeze boundary**.

All rows **shall** share:

| Shared identity |
|---------------|
| One `FreezeContext` |
| One `freezeEventId` |
| One `meetingId` |
| One `propertyId` |
| One attempt identity |
| One atomic work envelope |
| One authoritative source operation |
| One `freezeBoundaryAt` |

Every row's `frozen_at` **shall** derive from the same `freezeBoundaryAt`. Per-row timestamp generation for `frozen_at` is **prohibited**.

---

## 8. Target / mapping baseline

**Target:** `public.owner_vote_voter_snapshot`

New E-02 rows **shall** conform to the E-01-certified Voter Snapshot domain.

| Field | Semantics |
|-------|-----------|
| `id` | Target identity |
| `meeting_id` | From `FreezeContext.meetingId` |
| `property_id` | From `FreezeContext.propertyId` |
| `unit_no` | Normalized unit from PEC selection |
| `user_id` | From selected rank-1 source row |
| `role` | From selected rank-1 source row |
| `is_eligible` | Eligibility flag per mapping contract |
| `frozen_at` | Logical freeze instant — uniform `freezeBoundaryAt` |
| `created_at` | Persistence metadata |
| `freeze_event_id` | From `FreezeContext.freezeEventId` |

Correlation fields **shall** derive from the authoritative `FreezeContext`. `created_at` remains persistence metadata. `frozen_at` represents the logical freeze instant. These semantics **must not** be conflated.

---

## 9. Duplicate baseline

**RA-2.1-001** is hereby incorporated into the IU-2.1 Engineering Baseline.

| Condition | Authority | Outcome |
|-----------|-----------|---------|
| **Invalid duplicate** | Same `freezeEventId` + same normalized `unit_no` | **Fail closed** |
| **Valid condition** | Same `user_id` + different normalized `unit_no` when PEC independently selects that user as rank-1 for those units | **Permitted** |

Therefore: `user_id` alone **shall not** be used as the authoritative duplicate dimension.

Any earlier IU-2.1 design wording that treated same-event `user_id` collision as inherently invalid is **semantically superseded** by RA-2.1-001. No silent deduplication is permitted.

---

## 10. Count reconciliation baseline

Successful IU-2.1 materialization **shall** satisfy:

```
sourceEligible = materializedTotal = materializedEligible
rejectedCount = 0
```

**`sourceEligible`** means the number of PEC-selected rank-1 voter rows after eligibility filtering, unit normalization, and rank selection. It does **not** mean raw `property_members` row count.

Any unexplained count drift **shall fail closed**. Legacy NULL-linked rows **shall not** participate in new-event reconciliation.

---

## 11. Completeness baseline

IU-2.1 may report **MATERIALIZED** only when:

| Requirement | Status |

| All PEC-selected voters are represented | Required |
| All identities are valid | Required |
| All unit duplicate checks pass | Required |
| All correlations pass | Required |
| Counts reconcile | Required |
| `rejectedCount = 0` | Required |
| No partial success exists | Required |

This establishes **Complete Voter Set** for IU-2.1. It does **not** establish full Phase 2 **MI-3 Complete Materialization**. Full MI-3 requires IU-2.1 + IU-2.2 + IU-2.3.

## 12. Correlation baseline

Every new IU-2.1 row **shall** satisfy:

| Row field | Must equal |
|-----------|------------|
| `row.freeze_event_id` | `FreezeContext.freezeEventId` |
| `row.meeting_id` | `FreezeContext.meetingId` |
| `row.property_id` | `FreezeContext.propertyId` |

**Prohibited:** cross-event rows · cross-meeting rows · cross-property rows · alternate correlation roots.

Any correlation mismatch **shall fail closed**.

---

## 13. Immutability baseline

All new E-02 Voter Snapshot rows are event-linked. Therefore `freeze_event_id IS NOT NULL` for IU-2.1 E-02 output.

These rows participate in the E-01-certified event-linked immutability model.

IU-2.1 **shall not** rely on:

| Prohibited correction |
|-----------------------|
| Post-materialization UPDATE |
| Post-commit DELETE |
| DELETE + rebuild |
| Silent correction |

Post-commit correction / reissue remains **E-06** scope.

---

## 14. Legacy preservation baseline

Legacy rows where `freeze_event_id IS NULL` remain historical legacy snapshot state.

IU-2.1 **shall not:**

| Prohibited action |
|-------------------|
| UPDATE legacy rows |
| DELETE legacy rows |
| Rebuild legacy rows |
| Reinterpret legacy rows |
| Include legacy rows in new-event reconciliation |

New E-02 materialization is scoped exclusively to the current Freeze Event. This is the authoritative legacy coexistence rule.

---

## 15. Materialization algorithm baseline

The authoritative conceptual sequence is:

```
FreezeContext received
        ↓
MATERIALIZATION_READY verified
        ↓
PEC source read
        ↓
PEC eligibility filtering
        ↓
unit normalization
        ↓
rank-1 selection
        ↓
source completeness validation
        ↓
source → target mapping
        ↓
identity validation
        ↓
unit duplicate validation
        ↓
correlation validation
        ↓
stage event-linked rows inside existing atomic envelope
        ↓
count reconciliation
        ↓
voter-set completeness verification
        ↓
MATERIALIZED
```

No independent commit may occur within IU-2.1.

## 16. Result contract baseline

| IU-2.1 outcome | Meaning |
|----------------|---------|
| **MATERIALIZED** | IU-2.1 materialization success |
| INVALID_SOURCE | Source population or PEC failure |
| CORRELATION_FAILURE | Correlation mismatch |
| DUPLICATE_FAILURE | Unit duplicate violation per RA-2.1-001 |
| PERSISTENCE_FAILURE | Staging or persistence failure |
| TRANSACTION_FAILURE | Transaction envelope failure |

Only **MATERIALIZED** means IU-2.1 materialization success.

No IU-2.1 result means **COMMITTED** or Phase 2 aggregate **COMMIT_READY**. No partial-success outcome exists.

---

## 17. Failure / rollback baseline

Every IU-2.1 failure **fails closed**.

IU-2.1 **shall not** own an independent rollback transaction. Failure propagates to the Phase 1 transaction owner. The certified Phase 1 Rollback Contract remains authoritative.

A failed attempt **shall not** leave durable event-linked IU-2.1 voter rows. No silent retry inside the envelope. No failure-to-success conversion.

---
