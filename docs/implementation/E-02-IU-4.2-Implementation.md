## 7. Verification Model

### Verification chain

```
Repository Entry
  → Event Selection / Identity Resolution
  → Meeting Correlation
  → Property Correlation
  → Snapshot Correlation
  → Bundle Assembly
  → Correlation Assertion (assertBundleCorrelation)
  → Read Mode Classification
  → Authority Classification
  → Integration Result
```

### Concept separation (mandatory)

| Concept | Meaning |
|---------|---------|
| Successful bundle load | Repository returned `{ ok: true, data: bundle }` |
| Authoritative primary proof | Only from `loadByOwnerVoteMeetingId` with `readMode = event_linked` and primary event selected |
| Explicit event proof | Only from `loadByFreezeEventId` — proves requested event, not primary authority |
| Readable | Bundle load succeeded |
| Complete (read contract) | All queried artifacts returned per repository contract |
| Complete (Phase 2 materialization) | **Separate authority — not certified by read repository** |
| COMMITTED | **Composite write/audit authority — not inferable from read success** |

**Locked distinctions:**

```
Successful bundle load ≠ authoritative primary proof in every entry mode
Successful bundle load ≠ COMMITTED
Readable ≠ Complete ≠ Authoritative Primary ≠ COMMITTED
Cross-entry equivalent bundle ≠ COMMITTED proof
```

## 10. Cross-Entry Equivalence Verification

### Definition: PRIMARY CROSS-ENTRY EQUIVALENCE

Given meeting **M** and primary freeze event **E** where:

1. `loadByOwnerVoteMeetingId(M)` selects primary event **E** (`is_primary = true`, newest `created_at` if multiple — see IVQ-002)
2. `loadByFreezeEventId(E)` loads the same event

Then both paths **shall** produce equivalent frozen event-linked content on:

| Comparable field | Equivalence rule |
|------------------|------------------|
| `meeting.id` | Equal |
| `meeting.propertyId` | Equal |
| `freezeEvent.id` | Equal |
| `freezeEvent.isPrimary` | Equal (true for primary path) |
| `readMode` | Both `event_linked` |
| `voterEntries` set | Same membership · same field values per id |
| `resolutionSnapshot` | Same identity/content or both null |
| `frozenMotions` set | Same membership · same field values per id |
| Correlation facts | Both pass `assertBundleCorrelation` |

### What equivalence does NOT prove

```
PRIMARY CROSS-ENTRY EQUIVALENCE ≠ COMMITTED PROOF
```

Cross-entry equivalence verifies **repository integration consistency** only.

### Preconditions

| Condition | Cross-entry equivalence |
|-----------|------------------------|
| Primary event exists for M | Applicable |
| Legacy meeting (no primary event) | **Not applicable** — meeting entry returns `legacy_meeting`; event entry requires explicit event id |
| Non-primary event E′ | Meeting entry selects primary E ≠ E′ — **no equivalence expected** |
