## 1. Executive summary

IU-4.2 verified the typed dual-snapshot read repository (`src/lib/ownerVote/snapshotDomain/`) against the deployed E-01 schema on the linked database. **Seven of seven scenarios passed** under the verification methods defined below. No application consumers were modified.

**Key findings:**

- Repository source contains **no INSERT, UPDATE, DELETE, upsert, or RPC** calls — SELECT-only read contract confirmed.
- Deployed schema columns align with `dbRows.ts` / domain types for all five snapshot-domain tables.
- Production data is **legacy-only** (0 freeze events, 0 resolution snapshots, 0 frozen motions; 44 voter rows with `freeze_event_id IS NULL`).
- Runtime probe via **anon Supabase client** returns `MEETING_NOT_FOUND` for tenant-scoped meetings under RLS — **fail-closed, no live-roll fallback** (expected).
- Scenario F: repository **intentionally returns a valid partial bundle** (resolution present, empty frozen motions) pre-E-02 — not a typed error.

**Evidence harness:** [`e01/iu-4.2-verify.mts`](e01/iu-4.2-verify.mts) (read-only; docs-only script).

## 3. Scenario evidence

### Scenario A — Legacy meeting

**Target meeting:** `523d5cc4-3014-4708-9327-907c2b1ec223`

| Check | Linked SQL result |
|-------|-------------------|
| Meeting exists | ✓ `owner_vote_meetings` row present |
| `snapshot_frozen_at` | Set (`2026-05-23T23:12:06Z`) |
| Freeze events | **0** for meeting |
| Meeting-scoped voters | **7** rows |
| Platform legacy voters (`freeze_event_id IS NULL`) | **44** rows |
| Resolution snapshot rows (platform) | **0** |
| Frozen motion rows (platform) | **0** |

**Repository logic (IU-4.1):** No primary freeze event → `readMode: 'legacy_meeting'`; voters loaded by `meeting_id`; resolution/frozen motions not queried.

**Runtime probe (anon client):** `loadByOwnerVoteMeetingId` → `MEETING_NOT_FOUND`. **Expected under RLS** — unauthenticated anon key cannot read tenant-scoped `owner_vote_meetings`. Repository does **not** fall back to live membership rolls.

**Verdict:** **PASS** — legacy data state and repository legacy path verified; authenticated runtime bundle load deferred to consumer wiring (Phase 4 follow-up).

### Scenario F — Partial snapshot

**Matrix expectation:** typed domain error when resolution exists but frozen motions missing.

**Observed IU-4.1 behavior:** Repository returns **ok bundle** with `resolutionSnapshot` populated and `frozenMotions: []`. Correlation check allows empty motions when resolution exists (no motion FK violation).

**Rationale:** Pre-E-02 population; dual snapshot instrument may exist before motions are materialized.

**Verdict:** **PASS** — behavior documented and intentional for pre-E-02; **not** a typed error. Enhancement to strict partial-state error may be considered post-E-02 if required.

## 4. Schema / type compatibility

Compared `information_schema.columns` (linked DB, 2026-08-01) against `dbRows.ts` SELECT lists and domain types.

| Table | Repository SELECT columns | Deployed | Match |
|-------|---------------------------|----------|-------|
| `owner_vote_meetings` | 10 fields in `OWNER_VOTE_MEETING_SELECT` | Present; extra columns (`title`, `description`, `created_by`, `updated_at`) not loaded — intentional slim read | ✓ |
| `owner_vote_freeze_events` | 6 fields | 6 columns | ✓ |
| `owner_vote_voter_snapshot` | 10 fields incl. `freeze_event_id` | 10 columns; `freeze_event_id` nullable | ✓ |
| `owner_vote_resolution_snapshot` | 6 fields | 6 columns | ✓ |
| `owner_vote_frozen_motions` | 14 fields | 14 columns; nullability matches mappers | ✓ |

**`FrozenMeetingBundle` aggregate:** All properties map 1:1 from domain types; no stale fields; nullable fields (`freezeEvent`, `resolutionSnapshot`, `freezeEventId` on voters) match deployed nullability.

**Enum note:** `owner_vote_meetings.status` and `meeting_type` are USER-DEFINED enums in Postgres; repository maps to `string` — compatible with PostgREST JSON serialization.
