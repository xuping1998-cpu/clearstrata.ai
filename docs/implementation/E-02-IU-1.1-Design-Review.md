## 5. Design findings

### Strengths

| # | Finding |
|---|---------|
| S-1 | Clear separation of **identity design** (IU-1.1) from **validation** (IU-1.2) and **transaction boundary** (IU-1.3) — aligns with Phase 1 plan |
| S-2 | `FreezeContext` contract provides a single correlation carrier — directly mitigates R-002 (lost correlation) |
| S-3 | Lifecycle explicitly distinguishes **Candidate / Staged / Committed / Abandoned** — supports Recovery Model RM-1 and RM-3 without conflating rollback with correction |
| S-4 | Uniqueness strategy layers orchestration checks on E-01 persistence policy — extends baseline without schema redesign |
| S-5 | Legacy `freezeEventId = null` path explicitly preserved — backward compatibility consistent with E-01 acceptance evidence |
| S-6 | Design consumes E-01 `FreezeEvent` domain type and persistence entity without redefining architecture |

### Risks

| ID | Risk | Severity | Review assessment |
|----|------|----------|-------------------|
| R-001 | Duplicate identity under concurrent invoke | Medium | **Mitigated in design** — uniqueness §6.8; Implementation Review must verify enforcement |
| R-002 | Lost correlation across Phase 2 hand-off | Medium | **Mitigated in design** — single context owner §6.3 |
| R-003 | Identity reuse after abandoned attempt | Low | **Mitigated in design** — new UUID per attempt §6.2 |

No **unmitigated** design risks identified.

### Clarifications

| # | Clarification |
|---|---------------|
| C-1 | **IU sequencing:** Identity **model** is defined in IU-1.1; **assignment** occurs at orchestration runtime after IU-1.2 validation passes (Implementation §6.1). This is consistent with phase IU order 1.1 → 1.2 → 1.3 — IU-1.1 delivers the contract; IU-1.2 gates assignment timing. |
| C-2 | **CM-7 enforcement** is designed in IU-1.1 but **verified** in Phase 4 (IU-4.2) — acceptable deferral. |
| C-3 | **Staged row insert** (uncommitted) is owned by IU-1.3 transaction boundary; IU-1.1 defines identity states only — no overlap violation. |

### Open questions

**None blocking.**

| # | Question | Disposition |
|---|----------|-------------|
| Q-1 | Idempotent return vs explicit conflict when committed primary exists? | Architecture Authority §13 allows both — Implementation Review shall pick one per meeting policy; not a design block |

### Required changes

**No blocking design issues.**

No revisions to [`E-02-IU-1.1-Implementation.md`](E-02-IU-1.1-Implementation.md) required before Implementation Review.
