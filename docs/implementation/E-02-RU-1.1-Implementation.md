## 6. Identity model

### 6.1 Certified contract (preserved)

| Element | Rule |
|---------|------|
| **`primaryAuditId`** | Independent UUID PK (`id`) — **`primaryAuditId ≠ freezeEventId`** |
| **`freeze_event_id`** | Mandatory FK → `owner_vote_freeze_events.id` |
| **Cardinality** | Exactly **one** Primary Audit per committed `freeze_event_id` |
| **Uniqueness dimension** | **`UNIQUE(freeze_event_id)`** — **not** `UNIQUE(meeting_id)` |

### 6.2 Meeting primary vs freeze-event audit

| Constraint | Scope | Purpose |
|------------|-------|---------|
| `owner_vote_freeze_events_one_primary_per_meeting` | Meeting-level | At most one **primary freeze event** per meeting (existing) |
| `UNIQUE(freeze_event_id)` on audit table | Freeze-event-level | Exactly one **Primary Audit** per freeze event identity |

After rollback/retry, a meeting may accumulate **multiple** freeze event identities over time; only **committed** events receive durable Primary Audit rows. Rolled-back events leave **no** durable audit (transaction rollback).

## 13. First-class vs JSONB decision matrix

| Evidence element | Storage | Reason |
|------------------|---------|--------|
| Identity / correlation IDs | **First-class columns** | Query · FK · uniqueness |

| `freeze_boundary_at` · `committed_at` | **First-class columns** | Timestamp semantics |

| Marker alignment detail | `marker_evidence jsonb` | Artifact E compatibility |
| Artifact F compatibility snapshot | `meeting_lifecycle_compatibility jsonb` | **Evidence only** |
| Server orchestration metadata | `commit_evidence jsonb` | Extensible correlation |

**Principle:** Critical identity / correlation / count / timestamps = first-class. Extensible evidence = JSONB.

## 16. transaction_outcome semantics

Audit row inserted **inside** open DB transaction as **INSERT-ONCE final form** (§20).

| Concept | Design |
|---------|--------|
| Pre-COMMIT (in-transaction) | Row visible only within transaction scope |
| External durability | Row exists only after successful **COMMIT** |
| False COMMITTED prevention | `transaction_outcome` **SHALL NOT** equal runtime **COMMITTED** state label |

**Proposed value at INSERT:**

| Value | Meaning |
|-------|---------|
| `ATOMIC_ENVELOPE_MEMBER` | Audit staged as A–G member pending transaction COMMIT |

**Prohibited at INSERT:** `COMMITTED` · `AUDIT_PREPARED` as durable external authority labels.

Durable **COMMITTED** runtime state remains **RU-1.3** orchestration scope — not implied by audit row alone.

**Status:** **PROPOSED** — ERQ-1.1-007 **DESIGN REVIEW**.

## 17. committed_at semantics

IU-3.2 §11: `committed_at` = **recommended** · **not sole COMMITTED authority**.

### Options analyzed

| Option | Assessment |
|--------|------------|
| **A: `transaction_timestamp()` at INSERT** | **Preferred** — same value for all statements in transaction; row durable only after COMMIT; semantic = transaction commit instant |
| B: `statement_timestamp()` | Acceptable alternative — Design Review choice |
| C: Post-commit UPDATE | **REJECTED** — violates INSERT-ONCE · atomicity · PAF-10 |
| D: Omit `committed_at` | **REJECTED** — IU-3.2 recommends dedicated field |

**Proposed:** `committed_at timestamptz NOT NULL` populated at INSERT with `transaction_timestamp()` inside atomic envelope.

```
NO SECOND COMMIT-SIDE AUDIT UPDATE
committed_at ≠ SOLE COMMITTED AUTHORITY
created_at alone ≠ commit authority
```

**Status:** **PROPOSED** — ERQ-1.1-006 **DESIGN REVIEW**.

## 20. INSERT-ONCE design

**Preferred model:**

```
INSERT ONCE (final evidence form) → COMMIT ONCE → NEVER UPDATE
```

| Benefit | |
|---------|---|
| Immutability compatibility | No UPDATE after INSERT |
| Partial audit prevention | Single authoritative row |
| Post-commit repair elimination | PAF-10 |

Audit row inserted in RU-1.2 atomic envelope with complete evidence fields — **certified contract supports** (IU-3.2 staged audit in same transaction).
