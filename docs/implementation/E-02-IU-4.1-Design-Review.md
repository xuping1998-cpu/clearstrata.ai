## 10. ARQ-015 — Authoritative ruling

### Repository fact

`fetchFreezeEventById` (used by `loadByFreezeEventId`) filters **only** by `id`:

```typescript
.eq('id', freezeEventId).maybeSingle()
```

**No `is_primary` predicate.** If the row exists and correlation validates, bundle loads with `readMode: 'event_linked'` regardless of `is_primary` value.

### Ruling

**ARQ-015 answer: B — EXPLICIT EVENT IDENTITY LOOKUP**

| Entry point | Semantic classification | `is_primary` required? |
|-------------|----------------------|------------------------|
| `loadByOwnerVoteMeetingId(meetingId)` | **AUTHORITATIVE PRIMARY LOOKUP** | **YES** — meeting → primary event → bundle |
| `loadByFreezeEventId(freezeEventId)` | **EXPLICIT EVENT IDENTITY LOOKUP** | **NO** — known event id → that exact event → bundle |

### Locked boundaries (contract clarification — not repository redesign)

```
EVENT IDENTITY LOOKUP ≠ AUTHORITATIVE PRIMARY LOOKUP

Successful loadByFreezeEventId()
does NOT by itself prove:
  - is_primary
  - COMMITTED
  - authoritative current meeting freeze
  - Primary Audit existence
```

Non-primary events with valid correlation may serve **historical / diagnostic / explicit-event** reads. They **must not** be promoted to authoritative committed primary without separate composite evidence (Phase 3 COMMITTED contract).

### E-01 modification required?

**NO.** Dual entry points eliminate ambiguity through **contract classification**. Existing code behavior is **consistent** with B; Implementation correctly proposed clarification without fork.

| Checklist E — ARQ-015 | **6 / 6 PASS** |
