## 4. Transaction Entry baseline

A **new** Freeze Transaction **may open** only when **all** of the following hold:

| Condition | Requirement |
|-----------|-------------|
| Validation Result | **VALID** |
| Candidate identity | Freeze Event identity **has been assigned** |
| No superseding primary | No committed primary supersedes the attempt |
| No competing owner | No competing transaction owner holds the freeze boundary |

The following **shall not** open a new transaction:

| Outcome | Rule |
|---------|------|
| **INVALID** | Fail closed — no transaction |
| **IDEMPOTENT RETURN** | Return existing committed primary — no new transaction |
| **RETRYABLE** | No new transaction |
| **CONFLICT** (reserved) | Fail closed if emitted |

---

## 5. Transaction ownership baseline

| Rule | Requirement |
|------|-------------|
| **Cardinality** | Exactly **one** authoritative Freeze Transaction owner per meeting freeze boundary |
| **Owner** | Freeze Engine orchestration |
| **Association** | `meetingId` · `propertyId` · `freezeEventId` · attempt identity · transaction state |
| **Transfer** | Ownership **shall not** transfer implicitly |
| **Downstream** | Phase 2 and Phase 3 consume the same authoritative transaction envelope |

---

## 6. Transaction state baseline

Authoritative Phase 1 state model:

```
UNOPENED
    ↓
  OPEN
    ↓
MATERIALIZATION_READY
    ↓
COMMIT_READY
    or
ROLLING_BACK
    ↓
ROLLED_BACK
```

| State | Definition |
|-------|------------|
| **UNOPENED** | Transaction prerequisites not satisfied |
| **OPEN** | Authoritative transaction boundary acquired |
| **MATERIALIZATION_READY** | Transaction may hand control to Phase 2. **Does not** certify snapshot persistence |
| **COMMIT_READY** | Phase 2 has reported successful materialization inside the same atomic envelope. **Does not** mean the transaction has committed |
| **ROLLING_BACK** | Pre-final-commit failure requires rollback |
| **ROLLED_BACK** | Rollback completed. Terminal for that attempt |

**Committed** terminal state is **Phase 3-owned** — not an IU-1.3 state.

---

## 7. Commit boundary baseline

The following distinction is **authoritative**:

**COMMIT_READY ≠ COMMITTED**

### IU-1.3 owns

| Responsibility |
|----------------|
| Transaction boundary |
| Transaction ownership |
| Rollback boundary |
| Failure propagation |
| **COMMIT_READY** hand-off |

### IU-1.3 does NOT own

| Responsibility | Owner |
|----------------|-------|
| Final atomic commit | Phase 3 |
| Meeting freeze marker | Phase 3 |
| Phase transition | Phase 3 |
| Primary audit | Phase 3 |
| Committed terminal state | Phase 3 |

## 8. Atomic work envelope baseline

Phase 1 establishes **one authoritative atomic work envelope** for downstream E-02 execution.

```
Transaction Open
        ↓
Phase 2
  · Voter Snapshot Materialization
  · Resolution Snapshot Materialization
  · Frozen Motion Materialization
        ↓
   COMMIT_READY
        ↓
Phase 3
  · Freeze Marker
  · Phase Transition
  · Primary Audit
  · Final Commit
```

| Rule | Requirement |
|------|-------------|
| Atomicity | All durable freeze artifacts **must ultimately commit** inside the same atomic work envelope |
| Phase 2 | **Shall not** open an independent freeze transaction |
| Phase 3 | **Shall not** reconstruct a separate freeze transaction |
| Correlation | Freeze Event identity **remains unchanged** throughout |

---

## 9. Rollback baseline

Any failure **before** successful Phase 3 final commit **requires rollback** of the entire atomic work envelope.

Rollback **shall leave no durable**:

| Artifact |
|----------|
| Voter Snapshot |
| Resolution Snapshot |
| Frozen Motions |
| Freeze marker |
| Phase transition |
| Primary audit |
| False committed Freeze Event |
| Partial correlated snapshot set |

Retry **may occur only after rollback** according to the Recovery Model and IU-1.1 / IU-1.2 baselines.

---

## 10. Failure propagation baseline

Failures **shall**:

| Rule |
|------|
| Propagate to transaction owner |
| Fail closed |
| Avoid partial commit |
| Avoid success conversion |
| Avoid silent in-envelope retry |

Retry belongs to **orchestration after rollback**.

## 22. Knowledge captured

| Principle | Statement |
|-----------|-----------|
| Contract nature | The Freeze Transaction Boundary is an **orchestration contract**, not a final commit operation |
| Sequencing | Validation **must precede** transaction entry |
| Identity prerequisite | Freeze identity **must exist** before the transaction opens |
| Envelope unity | Phase 2 materialization and Phase 3 final commit **must share one atomic envelope** |
| Readiness vs commit | **COMMIT_READY** is a readiness state, **not** a durable committed state |
| Rollback scope | Rollback owns **all pre-final-commit failure cleanup** |
| Retry timing | Retry occurs **only after rollback** |
