## 12. event_linked Mode

**Trigger:** `freezeEvent` row present after primary event resolution (RE-4.1-011).

### Selection semantics

| Step | Behavior (evidence) |
|------|---------------------|
| Entry via meeting | `fetchPrimaryFreezeEventForMeeting`: `is_primary = true`, newest `created_at` (RE-4.1-007) |
| Entry via freeze event id | Direct `fetchFreezeEventById` — **no `is_primary` filter** on this path |
| Voter rows | `owner_vote_voter_snapshot` WHERE `freeze_event_id = <event.id>` (RE-4.1-008) |
| Resolution | `owner_vote_resolution_snapshot` WHERE `freeze_event_id = <event.id>` — nullable result allowed |
| Motions | `owner_vote_frozen_motions` WHERE `freeze_event_id = <event.id>` |
| Meeting load | Always loaded; correlated to event's `owner_vote_meeting_id` |

### Correlation verification

`assertBundleCorrelation` enforces (RE-4.1-012):

- Freeze event `ownerVoteMeetingId` / `propertyId` match meeting
- Each voter row `meetingId` / `propertyId` match; in event_linked mode `freezeEventId` must match event
- Resolution snapshot `freezeEventId` / `ownerVoteMeetingId` match
- Each motion `freezeEventId` / `ownerVoteMeetingId` match; `resolutionSnapshotId` matches header when present

### Missing rows

| Case | Behavior |
|------|----------|
| No resolution row | `resolutionSnapshot = null` — **load succeeds** |
| No motion rows | `frozenMotions = []` — **load succeeds** |
| No voter rows | Empty array — **load succeeds** (correlation passes vacuously) |
| Correlation violation | `CORRELATION_MISMATCH` error |

### Primary / ambiguity

| Topic | Finding |
|-------|---------|
| Depends on `is_primary`? | **YES** on meeting entry path only |
| Reads `snapshot_frozen_at`? | Included in meeting snapshot — **not used for mode selection or COMMITTED** |
| Live source fallback? | **NO** — no `property_members` / resolutions queries |
| Multiple primary events | DB index `owner_vote_freeze_events_one_primary_per_meeting` expected to prevent; repository picks newest if data anomaly |

**Authority semantics:** `event_linked` = E-02 **preferred** read mode for event-correlated dual-snapshot bundles. **Does not alone prove COMMITTED.**

## 14. Authoritative Frozen Read Contract

For **already frozen / event-linked** governance state reads, E-02 **shall** use:

1. `FrozenMeetingBundleRepository.loadByFreezeEventId(freezeEventId)` — preferred when event id known
2. `FrozenMeetingBundleRepository.loadByOwnerVoteMeetingId(meetingId)` — when resolving primary event

Reads **shall** consume only:

- `owner_vote_meetings`
- `owner_vote_freeze_events`
- `owner_vote_voter_snapshot`
- `owner_vote_resolution_snapshot`
- `owner_vote_frozen_motions`

Reads **shall not** reconstruct frozen content from live mutable sources within this path.

## 15. No-Live-Reconstruction Contract

**Finding (RE-4.1-022 · RE-4.1-023):** Current E-01 repository **does not** query `property_members`, `owner_vote_resolutions`, or agenda tables. **No live fallback observed.**

| Rule | Status |
|------|--------|
| event_linked voter load uses frozen table only | **CONFIRMED** |
| Resolution/motion load uses frozen tables only | **CONFIRMED** |
| Repository supplements missing frozen data from live sources | **NOT OBSERVED** |

**IU-4.1 locks:** Once reading event-linked frozen state, **must not** re-read live sources to "complete" governance truth. If future code adds such fallback → **LIVE_RECONSTRUCTION_VIOLATION** risk (R-100).

Allowed live reads remain **only** in Certified Phase 1/2 materialization stages — **outside** IU-4.1 frozen repository read path.
