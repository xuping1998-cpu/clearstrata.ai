## 18. committed_at review — ERQ-1.1-006 (HIGH PRIORITY)

### Analysis

| Question | Answer |
|----------|--------|
| Can `committed_at` be truthfully populated **before** COMMIT as "commit timestamp"? | **NO** — PostgreSQL `transaction_timestamp()` is **transaction start reference**, not post-commit instant |
| Post-COMMIT UPDATE to set `committed_at`? | **PROHIBITED** — breaks INSERT-ONCE · immutability · PAF-10 |

### Design Review resolution

| Implementation proposal | Review disposition |
|-------------------------|-------------------|
| `committed_at` + `transaction_timestamp()` at INSERT | **CHANGES REQUIRED** (naming/semantics only) |

**Approved physical column:**

| Column | Semantics |
|--------|-----------|
| **`transaction_reference_at timestamptz NOT NULL`** | Populated at INSERT with `transaction_timestamp()` inside atomic envelope |

**Authoritative semantics (approved):**

```
transaction_reference_at = PostgreSQL transaction reference instant
                           = same value for all statements in the transaction
                           = durable ONLY IF the row survives COMMIT
                           ≠ literal post-commit clock
                           ≠ sole COMMITTED authority (PAF-15)
                           ≠ substitute for Runtime COMMITTED (RU-1.3)
```

IU-3.2 logical `commitTimestamp` / recommended `committed_at` **maps at physical layer** to **`transaction_reference_at` + `commit_evidence` + row durability** — composite evidence, not column rename of COMMITTED authority.

| **ERQ-1.1-006** | **RESOLVED WITH NOTE** — approved name `transaction_reference_at` |

**RA-RU-1.1-001** (see §41) — Implementation Review must consume approved naming.

**PASS WITH NOTE** (after rename authority)
